# Аудит кода, остаточных путей и проверок — 24 октября 2026

База: `61599c0a4211c9bce7477085600b32c451717c24` из `Mishokkka/Skyhold`, ветка `main`.

## Метод и границы

Проверка разделена на хранение/права/socket/миграции, расчётные движки и интерфейс/бой. Составлены графы статических и строковых динамических импортов, проверены manifest, публичные экспорты, композиция доменов, action registries, шаблоны, генераторы и запуск тестов. Кандидаты на удаление дополнительно проверены поиском по runtime, dev-коду и документации. Ошибки исправлялись после воспроизведения; критичные изменения получили независимое ревью.

Из 406 runtime-модулей 397 достижимы от `scripts/main.js`. Девять остальных сохранены: `scripts/apps/editors.js`, `scripts/data.js`, `data/schema.js`, `data/gm-rolls.js`, `data/laputa-import.js` и четыре исходных каталога `building-template-catalog/{culture,food,technology,war}.js`. Это фасады совместимости и входы генераторов. Отсутствие импорта от main само по себе не доказывает ненужность.

Ни статический граф, ни прохождение Node-тестов не доказывают отсутствие всех багов. Семантическое ревью сосредоточено на транзакциях, числовых/временных границах, взаимодействии подсистем, динамической диспетчеризации и кандидатах на удаление. Live Foundry, миграции, импорт Actors и запись данных мира не выполнялись.

Теперь перед таким commit сохраняется предыдущий корень. ## Что изменено в тестах и зачем

Семь файлов из `characterization:check` раньше при прямом запуске лишь экспортировали функцию, завершаясь с кодом 0 без assertions: Calendaria, context, economy, random-events, socket, storage и storage-operation. Добавлены main-module guards с реальным вызовом и ожиданием async-проверок. При импорте поведение не изменено; составные suites продолжают их вызывать.

В обычный `check` добавлена регрессия рыночного спроса и `core-safety-check`. Добавлена команда `npm run check:all`: она запускает combined suites и все различные Node-команды из существующих `*:check`, включая CSS. Сейчас это 125 команд; это не число уникальных тестов, поскольку suites и отдельные команды частично пересекаются. Нераспознанные команды и саморекурсия отклоняются явно. Ошибки собираются до конца прогона, затем команда завершается неуспешно.

Обычный `check` остаётся более узким. `lint`, `perf:budget`, генераторы, упаковка и диагностический `ships:balance` не входят в новый агрегатор. Набор не обращается к запущенному Foundry.

`.gitattributes` закрепляет LF для расширений, проверяемых structure suite: обычный Windows clone с autocrlf иначе нарушал собственный контракт репозитория ещё до запуска поведенческих проверок.

Полный прогон выявил также уже существовавшее падение `economy-settlement-scenario-check`: оно воспроизведено на неизменённой базе `61599c0`. Сценарий назначал старые QD/слоты в здания с актуальным `labor.mode = staff`, поэтому производство не работало. Fixture переведён на реальные штатные договоры с зарплатой, общие цели производства и действующие QD-задания полей/обслуживания. Добавлена валидация hybrid labor. Все семь двухлетних вариантов проходят с прежними требованиями: точное питание, отсутствие долгов, минимум 10% свободного труда, последствия пропущенного посева и восстановление после объявленной помощи. Нормальные варианты сохранили 41–45% минимального свободного труда; правила runtime не менялись ради сценария.

AST-сверка изменённых существующих dev-файлов: 1096 исходных assertion sites, 1158 после изменения. Два assertion-вызова рыночных обёрток заменены проверками действующих результатов с прежними ожидаемыми значениями; остальные исходные вызовы сохранены. Новые `core-safety-check` и проверки самого агрегатора учитываются отдельно. Это счётчик мест в исходниках, а не числа выполненных тестов.

Тестовые файлы не удалялись. Не найдено проверки, которую можно безопасно объявить бесполезной только из-за пересечения с соседней suite. Изолированный запуск доменных команд полезен для диагностики. Proposal/scenario checks сохраняют требования к каталогу и балансу, но сами по себе не доказывают исполнение соответствующего runtime-пути. Проверки текста исходников полезны для архитектуры, lazy boundaries и запрещённых API; они не заменяют регрессии поведения. Некоторые импортируемые тестовые модули всё ещё имеют top-level assertions, поэтому часть команд повторяет работу.

В этой версии репозитория нет GitHub Actions workflows. Наличие команд в package.json не обеспечивает их автоматический запуск на PR. Подключение CI с `check:all`, `lint` и отдельным контролем performance budget остаётся рекомендацией; workflow в этот PR не добавлен.

## Остаточные риски и ручная проверка

Допустимая очень большая входящая поставка по-прежнему может содержать много партий. Новый общий лимит партий был бы изменением политики продукта; в этом PR устранено разбиение уже невозможных покупок.

Node-моки не проверяют фактическую доставку senderId, гонки нескольких клиентов, propagation настроек, CSS/layout, браузерный фокус и хуки Calendaria. Вручную в Foundry 13.351 / Forbidden Lands 13.0.5 и поддерживаемом Foundry 14:

1. ГМ: изменить каталог ресурсов и выполнить складскую операцию. Игрок: открыть доступный каталог/склад, выполнить разрешённую складскую операцию; проверить read-only отказ и сообщение об ошибке соединения. Успешное действие должно примениться один раз.
2. Два ГМа: сохранить разрешённые изменения через authority-GM, проверить обновление окон и конфликт устаревшей revision.
3. ГМ: на тестовой копии проверить восстановление после прерванного сохранения; данные и метаданные должны относиться к одной revision.
4. ГМ: оформить/доставить или отменить несколько рыночных заказов одного ресурса; убедиться в согласованности остатка спроса, денег и резервов.
5. ГМ: проверить бой с одной и двумя доступными постройками, ранения/срок восстановления и итоговые записи.
6. Проверить удаление назначенного жителя, допустимое время Calendaria, tenday preview/apply и восстановление фокуса/состояния окон. Миграционные Preview можно просматривать; Apply требует отдельной авторизации.
