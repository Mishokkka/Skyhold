# Труд, типажи, выходные и план работ (v2)

Единая модель труда в четверочасовках (QD) за десятник без отдельных режимов занятости (`staff` / `qd` / `passive` / `legacy`), без `staffAppointment`, `workAllocationMode`, `assignedWorkerIds`, технического обслуживания зданий и устаревшего поля `salary`.

## Единицы времени и личный бюджет (`daysOffPerTenday`)

| Величина | Смысл |
|---|---|
| Календарный QD | Четверть суток; 40 QD за десятник |
| Выходные (`gm.labor.daysOffPerTenday`) | Настройка поселения `0..5` (по умолчанию `0`), снижает норму обычных QD жителя за десятник |
| Личный бюджет взрослого | `(10 - daysOffPerTenday) * 2` обычных QD (от `20` при 0 выходных до `10` при 5 выходных) |
| Личный бюджет ребёнка | `10 - daysOffPerTenday` обычных QD (от `10` до `5`); дети не работают сверхурочно |
| Сверхурочные | До `+10` QD за десятник для взрослых только на линиях/функциях с разрешением `overtimeAllowed` |
| Назначенные QD | Распределяются через `person.workAllocations[]` (`sourceId`, `functionId`, `normalQd`, `overtimeQd`, `volunteer`, `volunteerReason`, `wageDailyCopper`) |
| Физические QD | Реально отработанные дневные слоты бюджета (сохраняются внутри суток до начала нового дня) |
| Эффективные QD | Физические QD × производительность (ускоряют подготовку партий, но не календарную выдержку и не личные слоты) |

- Ограничения возраста, ранения, смерти, отсутствия, экипажа, стройбригады и эксклюзивной службы (`workAssignment`) проверяются до распределения и несовместимы с одновременными планами QD; прямое назначение не перезаписывает эксклюзивную роль без явной замены.
- При работе жителя более чем в одном здании или на нескольких функциях в интерфейсе отображается статус **«Смешанная»** с подсказкой-разбивкой QD по зданиям и функциям.
- Бесплатный труд требует явного `volunteer` / `volunteerLabor` (нулевая ставка сама по себе его не включает). Нехватка сырья не отменяет зарплату; неоплаченный работник не создаёт результат.

## Модель здания (`building.labor` v2)

Каждое здание описывается объектом `building.labor = { version: 2, capacityQd }`:

| Значение `capacityQd` | Поведение |
|---|---|
| `0` | Пассивный объект: не принимает работников, не требует ставок/назначений и не открывает рабочих целей (состояние постройки и специальные условия сохраняются) |
| Целое `N > 0` | Суммарный потолок рабочих QD всех назначенных жителей по всем функциям здания за десятник |
| `null` | Отдельного общего потолка QD у здания нет; ограничения задают сезонные этапы, стадо, ёмкость партий или календарь |

- Стандартные лимиты, ставки и пороги приведены в [справочнике каталога зданий](building-catalog.md).
- Для линий с `requiresCollection` и `collectQd > 0` частичный прогресс сбора сохраняется между днями и десятниками в `line.collectProgressQd` до завершения полного сбора.

## Типажи жителей

Типаж вычисляется функцией `workerTypeFromAttributes` из характеристик **≥ 5** (не из текста профессии):

| Характеристики `5+` | Типаж | Характеристики `5+` | Типаж |
|---|---|---|---|
| нет | Разнорабочий | ЛОВ + РАЗ | Ремесленник |
| СИЛ | Силач | ЛОВ + ЭМП | Посыльный |
| ЛОВ | Ловкач | РАЗ + ЭМП | Управленец |
| РАЗ | Умелец | СИЛ + ЛОВ + РАЗ | Мастеровой |
| ЭМП | Переговорщик | ЛОВ + РАЗ + ЭМП | Агент |
| СИЛ + ЛОВ | Строитель | СИЛ + РАЗ + ЭМП | Старшина |
| СИЛ + РАЗ | Механик | СИЛ + ЛОВ + ЭМП | Полевой вожак |
| СИЛ + ЭМП | Бригадир | все четыре | Мастер на все руки |

Селектор `РР*` означает сбалансированного разнорабочего (нет 5+, каждая ≥ 3, сумма ≥ 13). Поле `skill` удалено из модели жителя; `role` служит подписью назначения и не даёт бонуса.

## Квалификация и активация

- Допуск (`workerProfile.admission.hard`), обязательный состав (`workerProfile.composition`) и производительность — отдельные проверки. Условия И внутри группы и ИЛИ между группами сохраняются; один человек не закрывает два обязательных места. ГМ может выдать персональное исключение через `workerAdmissionOverrideIds`.
- Обязательный состав и **порог запуска `activation.minOperationalQd`** проверяются **по всему десятнику целиком** (не по мгновенной смене). Порог запуска бинарен (0% / 100%): пока суммарно выделенные QD меньше `minOperationalQd`, служба, доход или производственная функция отключены (0%); при достижении порога включаются на 100%. Ёмкость досуга (`qdPerCapacity`) масштабируется по выделенным QD только после преодоления порога.
- Редактор ГМа настраивает требования и целые проценты для типажей, прошлого и черт: для типажа и прошлого берётся первое совпадение сверху (обычно +25%/+50% и +10%), для черт — первое положительное (+10%) и первое отрицательное (−10%); вклады складываются (снизу ограничено 0).
- Социальные эффекты требуют выполненной основной функции здания ([building-social-contract.md](building-social-contract.md)); кухня трактира не заменяет отдельные QD обслуживания. Медицинские назначения учитывают фактическое присутствие врачей и пациентов.

## Планировщик, данные и совместимость

- Планировщик показывает работы, жителей, блокировки, общие цели, закрепления, подсказки «Смешанная» и черновик автопредложения (с учётом текущих запасов и сезона без обещания будущих поставок и глобального оптимума); запись идёт только по явному сохранению.
- Схема хранения: `building.labor = { version: 2, capacityQd }`, `person.workAllocations[]`, `holding.gm.labor.daysOffPerTenday`, `holding.workforcePlan` (`goals`, `locks`, `productionGoals`). Устаревшие поля (`maintenance`, `maintenancePointsPerTenday`, `assignedWorkerIds`, `staffAppointment`, `workAllocationMode`, `salary`) очищаются нормализаторами при загрузке мира без сброса пользовательских настроек и видимости скрытых объектов.
- Записи игроков по трудовому плану и контрольным назначениям всегда проходят через authority-GM сокет, проверку прав, `operationId` и ревизию.
- Владельцы контракта: `scripts/data/{labor-model,labor-budget,work-allocations,workforce-plan}.js`, `scripts/apps/domains/workforce-planner.js`, `scripts/engines/economy/building-service.js`. Проверки: `npm run work:check`, `npm run workforce:check`, `npm run workers:check`, `npm run hybrid:check`, `npm run maintenance:check`, [общая матрица](manual-foundry-smoke-matrix.md); отложенные идеи — [реестр](mechanics-expansion-roadmap.md).
