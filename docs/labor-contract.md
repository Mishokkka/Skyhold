# Труд, штат, типажи и план работ

Действующая гибридная модель труда (`staff` / `qd` / `passive` с сохранением совместимого `legacy`).

## Единицы времени и личный бюджет

| Величина | Смысл |
|---|---|
| Календарный QD | Четверть суток; 40 QD за десятник |
| Личный бюджет | По умолчанию 20 обычных рабочих QD взрослого (мировая норма 0–20); трудоспособный старший ребёнок — ≤ 10 QD без сверхурочных |
| Назначенные QD | Зарезервированное время: штат резервирует сотрудника целиком, QD-задания делят бюджет |
| Физические QD | Реально отработанные слоты; оплаченный простой штата показан отдельно |
| Эффективные QD | Физические QD × производительность (ускоряют подготовку, но не календарную выдержку и не личные слоты) |
| Выпуск | Целые единицы после труда, сырья, ожидания и сбора |

Ограничения возраста, ранения, смерти, отсутствия, экипажа и других постоянных назначений проверяются до распределения. Сверхурочные взрослого идут отдельными слотами с дневным пределом; автопредложение плана их не добавляет.

## Режимы здания

| Режим | Поведение |
|---|---|
| `staff` | Постоянные сотрудники (`workersMax`). Основная и резервная функции принадлежат этому зданию; при отсутствии основной работы слоты переходят на резервную без двойного расхода, остаток остаётся оплаченным простоем |
| `qd` | Задания на личные QD; необязательный `capacityQd` ограничивает суммарные физические QD здания. Цель выпуска принадлежит линии, а не каждому работнику |
| `passive` | Регулярных работников нет; пассивный доход возникает только по явному правилу здания |
| без `labor` | Совместимый `legacy`; обычная загрузка не угадывает новый режим |

- Штатный договор резервирует жителя даже при норме 0 и несовместим с другими гражданскими назначениями. Ошибка одного договора не блокирует исправных коллег, но нехватка минимального состава блокирует функцию.
- Техобслуживание назначается отдельно и не занимает производственную мощность. Стройбригады, военная служба и корабельная команда сохраняют собственные правила постоянной занятости.

## Оплата

- 2 обычных физических QD = 1 дневная ставка; 1 сверхурочный QD = 1 полная дневная ставка. Итог по жителю округляется вверх до целой ММ один раз (ставка 12, 20 обычных + 3 сверхурочных = 156 ММ независимо от эффективности).
- Штат оплачивается по ставке договора (включая резерв и простой); в заданиях действуют ставки конкретных работ. Один слот не оплачивается дважды.
- Бесплатный труд требует явного `volunteer` / `volunteerLabor` (нулевая ставка сама по себе его не включает). Нехватка сырья не отменяет зарплату; неоплаченный работник не создаёт результат.

## Типажи жителей

Типаж вычисляется функцией `workerTypeFromAttributes` из характеристик **≥ 5** (не из текста профессии):

| Характеристики `5+` | Типаж | Характеристики `5+` | Типаж |
|---|---|---|---|
| нет | Разнорабочий | ЛОВ + РАЗ | Ремесленник |
| СИЛ | Силач | ЛОВ + ЭМП | Посыльный |
| ЛОВ | Ловкач | РАЗ + ЭМП | Управленец |
| РАЗ | Умелец | СИЛ + ЛОВ + РАЗ | Мастеровой |
| ЭМП | Переговорщик | ЛОВ + РАЗ + ЭМП | Агент |
| СИЛ + ЛОВ | Строитель | СИЛ + РАЗ + ЭМП | Старшина |
| СИЛ + РАЗ | Механик | СИЛ + ЛОВ + ЭМП | Полевой вожак |
| СИЛ + ЭМП | Бригадир | все четыре | Мастер на все руки |

Селектор `РР*` означает сбалансированного разнорабочего (нет 5+, каждая ≥ 3, сумма ≥ 13). Поле `skill` удалено из модели жителя; `role` служит подписью назначения и не даёт бонуса.

## Квалификация и активация

- Допуск, обязательный состав и производительность — отдельные проверки. Условия И внутри группы и ИЛИ между группами сохраняются; один человек не закрывает два обязательных места. Профиль проверяется по реальной текущей смене.
- Редактор ГМа настраивает требования и целые проценты для типажей, прошлого и черт: для типажа и прошлого берётся первое совпадение сверху (обычно +25%/+50% и +10%), для черт — первое положительное (+10%) и первое отрицательное (−10%); вклады складываются (снизу ограничено 0).
- Социальные эффекты требуют подтверждённой работы основной функции ([building-social-contract.md](building-social-contract.md)); труд техника и кухня не засчитываются как досуг. Медицинские назначения учитывают фактическое присутствие врачей и пациентов.

## Планировщик, данные и совместимость

- Планировщик показывает работы, жителей, блокировки, цели, закрепления и черновик автопредложения (учитывает текущие запасы и сезон без обещания будущих поставок и глобального оптимума); запись идёт только по явному сохранению.
- Схема: `building.labor = { version: 1, mode, capacityQd }`; `person.staffAppointment` (`buildingId`, `primaryFunctionId`, `reserveFunctionId`, `wageDailyCopper`, `overtimeQd`, `volunteer`, `volunteerReason`, v1); `holding.workforcePlan` (v2: `goals`, `locks`, `productionGoals`).
- План v1 и смешанные поселения читаются; неизвестные/ошибочные данные сохраняются для явной диагностики; сохранения игрока проходят authority-GM.
- Владельцы: `scripts/data/{hybrid-labor,labor-budget,work-allocations,workforce-plan}.js`, `scripts/engines/workers/`, `scripts/apps/domains/workforce-planner.js`. Актуальные параметры зданий — [каталог](building-catalog.md); проверки — `workers:check`, `work:check`, `workforce:check`, `hybrid:check` и [общая матрица](manual-foundry-smoke-matrix.md); отложенные идеи (выходные, смены, сброс прогресса) — [реестр](mechanics-expansion-roadmap.md).
