## 1. Дом собраний

Дом собраний — постоянное место сходов, разбора общинных дел и хранения решений. Оно не заменяет суд, стражу или школу. Староста либо писарь ведёт текущие дела; власть и выборы отыгрываются за столом.

| Параметр | Норматив |
|---|---|
| ID | `meeting-house` |
| Название | Дом собраний |
| Этап | II — Развитое поселение |
| Тип / основное развитие | Инфраструктура / `culture` |
| Требования П/Т/К/В | `8/6/10/0` |
| Развитие П/Т/К/В | `0/1/3/0` |
| Строительство | 3 этапа; сложность `0`; денежная доплата `0` |
| Материалы | Wood 180; Stone 120; Cloth 20; Письменные материалы 10 |
| Канонические ресурсы | `wood:180`, `stone:120`, `cloth:20`, `parchment:10` |
| Штат | 1–2; староста, писарь; ставка 18 ММ/день |
| Содержание | база 36 / эксплуатация 18 ММ/месяц |
| Обслуживание трудом | 0 отдельных QD; повседневный уход включён в денежное содержание |
| Активация | 1 фактически работающий оплаченный или добровольный сотрудник; суммарно 20 обычных/сверхурочных QD за десятник; исправное здание без блокировки функции |
| Основная функция | `culture`; контроль порядка — эффект той же службы, без второго назначения, QD или оплаты за `defense` |
| Услуга | общественные сходы, ведение решений; `service.capacity:120`, `coverageKind:population` |
| Контроль | `generalFlat:1`, `maximum:1`; без институционального потолка и без дополнительной `control.capacity` |
| Репутация / глобальное довольство / условия труда | `0/0/0` |
| Жильё / склад / DR / производство / доход | 0 / 0 / 0 / нет / нет |
| Проекты учреждения | нет; решения хранятся в Политике, не дублируются в `serviceProjects` |
| Требования других зданий | нет; Центр Строительства не нужен |
| Участок | доступное и безопасное место общих собраний, вне опасного промышленного участка; проверка GM |
| Допуск работников | обычная гражданская служба без закрытой специальности; прошлое писаря или управленца полезно для образа, не создаёт производственных процентов |
| Типаж / прошлое / черты | производственные бонусы выключены; второй работник помогает набрать нужные QD, но не увеличивает фиксированный Контроль и охват |
| Развитие и повторы | развитие только от первого активного экземпляра; повтор добавляет самостоятельную мощность Контроля и охват, не слоты/Влияние Политики |
| Улучшение | Ратуша является старшим общественным институтом; автоматической замены или бесплатного улучшения нет |

При одном штатном сотруднике с 20 QD полная текущая денежная стоимость равна `180 + (36+18)/3 = 198 ММ/десятник`; отдельного технического обслуживания не требуется. При двух сотрудниках, разделяющих те же 20 QD, зарплата не удваивается. Два полных назначения по 20 QD стоят 360 ММ зарплаты и не дают второй фиксированный бонус.

Дом собраний вместе с Культурой не ниже 16 открывает Политику. Охват 120 не вводит потолок численности поселения для открытия: это вместимость общественной услуги, а не запрет самоуправления при 121 жителе. Работающая Ратуша также открывает Политику. Новый шаблон не строится автоматически при миграции.

## 2. Перераспределение развития

Каждое из четырёх зданий отдаёт ровно один пункт; базовые требования не меняются. Основная специализация сохраняется, стартовые здания не ослабляются.

| Здание | Было П/Т/К/В | Станет П/Т/К/В | Причина |
|---|---|---|---|
| Библиотека | `1/3/4/0` | `1/2/4/0` | один пункт систематизации знаний переносится в общественный учёт |
| Святилище | `0/0/4/0` | `0/0/3/0` | часть общинной организации отделяется от религиозной службы |
| Зал славы | `0/1/6/2` | `0/1/5/2` | поздний символ сохраняет сильную Культуру и военную память |
| Шпиль | `0/0/6/0` | `0/0/5/0` | один пункт общественной значимости передаётся действующему институту |

Снято `0/1/3/0`, Дом собраний добавляет `0/1/3/0`. Общая сумма и итог перед Цитаделью не меняются. Репутация и оба вида довольства этих четырёх зданий не меняются.

## 3. Логические зависимости

### Принцип

Числовые требования обозначают общий уровень поселения. Дополнительная зависимость нужна для реального институционального предшественника или обслуживающей инфраструктуры. Производство сырья само по себе не является строительным условием: Пекарня может покупать муку, Кузня — руду, Ателье — ткань. Это сохраняет специализацию и торговлю.

Различаются два вида условия:

- **Построить:** предшественник должен действовать при разрешении нового проекта. После начала проекта его последующая утрата не обнуляет стройку и не выключает готовое здание. Уже начатые и готовые здания при миграции не проверяются задним числом.
- **Работать:** конкретная услуга нужна постоянно. Её утрата останавливает соответствующую зависимую функцию с видимой причиной; здание и его имущество сохраняются. При новом условии миграция показывает будущую блокировку в Preview.

Массивы `requiredBuildingIds/requiredAnyBuildingIds` сохраняются; добавлены необязательные метки `prerequisiteModes` по ID зависимости. `construction` проверяется при создании проекта, `service` — для постоянно необходимой основной услуги. Без метки действует прежнее правило. Для условий «Работать» проверяется фактическая работоспособность поставщика услуги, включая оплату и труд, а не только существование неповреждённого экземпляра. Все 14 согласованных зависимостей с этими метками включены в v15.

## 4. Строгая граница миграции

Полный reset Лапуты уже выполнен — это информация пользователя от 2026-09-05. Старый snapshot и удаление Оливы не входят в следующий перенос.

Обычная загрузка и Preview не добавляют новые встроенные шаблоны, не подмешивают механические поля новой версии в существующие и не отмечают новую версию применённой. Отсутствие поля исправляется безопасным нейтральным значением только для формы данных; новое значение Контроля, активации, стоимости, зависимости или бонуса — изменение механики и ждёт Apply. При создании нового мира разрешён полный текущий встроенный набор.

Следующий Apply читает **текущее сохранение**, показывает только разницу каталога/зданий и связанных согласованных правил. Он сохраняет казну, ресурсы и партии, жителей, назначения, ранения, долги, рынок, журнал и состояние экземпляров по правилам сохранения ниже. Пользовательские шаблоны сохраняются. Для переопределённых пользователем механических полей Preview показывает конфликт и выбранное разрешение; изменения не скрываются под словом «нормализация».

Дом собраний добавляется только как доступный шаблон. Четыре уменьшения развития и новые зависимости отражаются в Preview. Новые строительные условия не инвалидируют уже начатые проекты. Несовместимый незавершённый производственный цикл, занятый удаляемый рецепт и другие небезопасные состояния блокируют перенос либо получают явное правило сохранения; возврат сырья/потеря прогресса не предполагаются молча.

Политика внедряется отдельным согласованным слоем. Нейтральный отсутствующий блок Политики не должен сам назначить правителя, дать хартию, списать дань или построить здание. Механика приезжих определяется [отдельным проектом](newcomer-arrival-proposal.md); вероятности остаются стартовой калибровкой. Она не подключается скрыто через обновление шаблонов.

### Сохранение экземпляров и безопасное применение

Сохраняются:

- ID экземпляра, пользовательское название, видимость, заметки, изображение, медиа и звук;
- жильцы, содержимое, назначения работников и явные исключения допуска;
- жизненный цикл, повреждения, ремонт и строительная бригада;
- для готового здания — готовность, для строящегося — доля прогресса и отметка уже вложенных материалов; возврата материалов нет;
- обслуживание и его backlog, выбранные торговые и производственные варианты, готовый выпуск совпадающей линии;
- состояние сельскохозяйственного цикла, поголовье, медицинские и религиозные настройки, проекты учреждений.

Утверждённые механические поля берутся из выбранной целевой редакции. Пользовательский шаблон и экземпляр с пользовательским `templateId` остаются без изменений. В Preview v15 отличия сохранённых механических значений от исходного шаблона требуют выбора «Оставить прежнее» или «Принять новое». При отсутствии сохранённого исходного шаблона сравнение использует известный встроенный шаблон; отличие считается неоднозначным, а не доказанной авторской правкой. Решение связано с исходным и предложенным значениями, может быть отменено и не переносится молча на изменившиеся данные. Состояние незавершённых производственных циклов проверяется отдельно и не снимается выбором рецепта. Сравнение выполняется в одинаковой нормализованной форме: добавленные загрузкой значения по умолчанию не выдаются за пользовательские правки. Шаблоны и экземпляры уже текущей версии сохраняются; повторная миграция не служит сбросом их настроек.


До записи разрешаются или блокируют применение:

- неоднозначный устаревший `templateId`, для которого нет безопасного прямого соответствия;
- незавершённый производственный цикл с зарезервированным сырьём или работой;
- готовый выпуск, который нельзя однозначно сопоставить новой линии;
- активная сельскохозяйственная культура или вид животных, отсутствующий в новом профиле;
- число занятых слотов выше нового `workersMax`;
- изменение revision, каталога или владений после построения Preview.


Сопоставление выполняется по стабильному templateId, известному alias или явно описанному старому instance ID; изменяемое название не служит ключом. `upgradesFromTemplateIds` не разрешает бесплатное улучшение. Старые общие назначения обслуживания и backlog получают явное правило перехода согласно проекту технического обслуживания; сохранение не означает их слепое копирование в несовместимую модель.

Целевой каталог: 119 зданий дерева и 2 сюжетных, плюс сохранённые пользовательские шаблоны. GM Apply использует одну split-storage транзакцию, pre-migration rollback и marker с версией, operationId и хешами результата. Повтор той же операции не пишет данные повторно; устаревший Preview требует пересчёта. Эти условия относятся к будущей реализации, а не к выполненной миграции.

## 5. Экономическое доказательство перед внедрением

Цель согласована пользователем: разумно организованное поселение с обычным питанием, подходящим жильём, охраной и оплаченной работой покрывает текущие расходы без обязательной постоянной субсидии. Специализация и торговля дают умеренный избыток; крупные стройки, война и роскошь требуют накоплений или внешнего дохода. Это не обещание прибыли произвольному набору зданий и не историческая универсальная формула.

Принято направление обслуживания: для большинства зданий только денежное содержание; отдельные QD — у технических объектов. [Нормы и интерфейс назначения](building-maintenance-proposal.md) предложены отдельно. Универсальные личные очки обслуживания больше не являются целевой моделью.

Старые `+136,5 ММ` и `−1423,5 ММ` остаются результатами усреднённой производственно-торговой цепочки. Они не объявляются балансом полного поселения. Новый проверочный сценарий должен пройти последовательные 24 десятника, а не умножить один средний период.

Обязательный набор: 20 живых жителей; полный обычный рацион; действительное жильё на всех; Колодец; пять Полевых хозяйств; Мельница и Пекарня; хранилище на пиковый урожай; Инструментальная мастерская и Рынок; необходимая охрана; доступные по выбранному маршруту учреждения. Все построенные объекты получают положенное денежное содержание; отдельный труд обслуживания — только работающая техника из согласуемого списка. Штат не предполагается бесплатным. Доход от патрона или контракта является явно задаваемым внешним источником, а не скрытой балансирующей суммой.

Входные условия: начало года, сезон каждого посева/сбора, стартовый запас зерна и его возраст, стартовая казна, уже построенный состав, правила календаря кампании, квалификация и доступность каждого работника. Стартовый продовольственный запас нужен до первого урожая и не считается бесплатным производством года. Параллельно считается повторяемый год с восстановлением такого же запаса на следующий сезон.

Каждый период: резерв труда по людям (не более 20 обычных QD), посев/уход/сбор, производство с фактической вместимостью и обеспеченными остатками, обслуживание, FIFO и порча, питание, зарплаты/содержание, конечный внутренний спрос и денежные поступления. Порядок должен совпасть с фактическим тендей-пайплайном; его нельзя переставлять ради выгодного результата. Вывод: голодные периоды, перегруз труда, просрочка и backlog, пики склада, минимальная казна, итог денег и запасов, необходимое внешнее финансирование.

Промышленная матрица: Металлургический завод, локальное/импортное сырьё, 50/100% загрузки, 30/120/300 км; входящая и исходящая доставка по реальным ценам, страховке, вместимости и срокам, реальные расходы содержания и труда. Строительная стоимость показывается отдельно вместе со сроком окупаемости, если годовой денежный поток положителен.

**Результат текущего прохода:** выполнены шесть последовательных годовых плановых сценариев, 12 промышленных сочетаний и девять вариантов специализации; [числа, предпосылки и границы проверки](economy-preparation-year-results-2026-09-05.md). Выборочное обслуживание освобождает труд, но внутреннего рынка недостаточно. Найден условно самоокупаемый план со специализацией, конечным внешним сбытом и явно указанным оборотным капиталом. Это модель с реальными чистыми расчётами, не полный runtime-эквивалентный прогон остановок, морали и случайных событий. Наличие нужных покупателей в текущем мире не подтверждено; рецепты по этому результату не менялись.

## 9. Что не следует исправлять автоматически

- Тепличный комплекс — дорогая круглогодичная услуга с убыточной прямой маржой; вода и персонал всё равно нужны.
- Высокая маржа яичной консервации проверяется вместе с кормом, уходом, поголовьем и конечным спросом. Выход 7 Tallow у козы закреплён данными; без новой калибровки это не опечатка для автоматической замены.
- Редкая древесина и мрамор требуют реального сюжетного ограничения доступа. Запас товара и его базовая стоимость не гарантируют продажу.
- Импорт сырья допустим; собственная цепочка каждого ресурса не становится обязательным условием строительства.
- Автоматический результат проектов учреждений, платное улучшение здания, машинная география участков и отношения с отдельными рынками отложены; отсутствие этих механик не разрешает подменять их бесплатным эффектом.
