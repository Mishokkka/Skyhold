# Публичный viewer: отдельный проект

Статус: **не реализован и не опубликован**. Это предложение статического сайта по явно экспортированному публичному снимку. Текущий модуль не синхронизирует сайт и не публикует настройки мира.

## Рекомендуемая первая версия

ГМ выбирает публичные владения, получает предпросмотр состава экспорта, скачивает JSON и вручную публикует его со статическим viewer. Сайт показывает дату снимка, сводку владения, жителей, здания и допустимые складские итоги. Он не отправляет команды обратно в Foundry.

Первая версия не требует аккаунтов игроков, прямого доступа к world settings, секретного ключа в браузере или постоянного соединения с запущенной игрой. Дальнейшая автоматическая публикация — отдельная интеграция с явным разрешением.

## Публичный договор данных

Нужны версия схемы, время экспорта, ревизия источника, выбранные публичные владения и только разрешённые поля. Это новый проектируемый формат файла, не действующая схема хранения мира.

| Раздел | Предлагаемое содержимое |
|---|---|
| Владение | Публичное имя, тип, описание, изображение и разрешённые сводные показатели |
| Жители | Публичные карточки и согласованные групповые сведения; без darkSecret, GM-заметок, прав и служебных связей |
| Здания | Публичные экземпляры и их представление; скрытый шаблон не раскрывается через одноимённое здание |
| Склад/экономика | Только выбранные ГМом итоги; без сырых операций, скрытых контрагентов и внутренних снимков |
| Изображения | Явно разрешённые публичные URL/копии; относительный путь Foundry сам по себе не публикует файл |

Экспорт строится по разрешённому набору полей с вложенной фильтрацией, а не удалением нескольких известных секретных ключей из полного root. Скрытый объект нельзя раскрыть через счётчик, историю, ссылку или название контрагента. Это граница именно публичной публикации, отличная от доверенного игрового стола.

ГМ просматривает содержимое: механическая фильтрация не распознаёт сюжетный секрет в обычном публичном имени. JSON доступен читателю целиком, даже если viewer не рисует поле; удаление файла позже не стирает опубликованную историю Git.

## Действия и ограничения

1. Выбор владений и разделов, проверка доступа ГМа.
2. Построение из согласованного read-only снимка без мутации источника.
3. Предпросмотр выгружаемых объектов и предупреждений о недоступных изображениях.
4. Явная команда скачивания; результат называется «Файл экспортирован», а не «Сайт обновлён».
5. Ручная публикация выбранным владельцем способом; viewer показывает последний экспорт при закрытом Foundry.

Обновление снимка заменяет публичное состояние, а не применяет события повторно. Viewer должен сообщать несовместимую версию и ошибку загрузки. Поиск, адаптивная ширина и доступность нужны до расширенной аналитики.

## Что согласовать и проверить

До реализации выбрать первый состав публичных полей, размещение, политику изображений и процесс отзыва опубликованного материала. Публикация и её учётные данные отдельно разрешаются владельцем; проект не даёт такого разрешения.

Будущие проверки: неизменность исходника; вложенные GM-only объекты и счётчики; устаревший/неполный экспорт; повтор без дублей; несовместимая версия; недоступные изображения; пустые/крупные владения; клавиатура и узкий экран. Live Foundry и публичный сайт проверяются раздельно. Точные пути файлов и внешние API следует выбрать при реализации, а не поддерживать сейчас список несуществующих модулей.
