## Производство и совместимость

Пользователь явно согласовал совместимое расширение хранения. Необязательное поле линии `workReservedInputs` содержит чек версии 1: конкретные ресурсы, складские метаданные, партии и деньги. Оно создаётся при резервировании новой партии и удаляется после её завершения. Обычная складская оплата сохраняет прежний контракт; чек возвращается только в явно запрошенном производственном режиме.

Пример: выпуск 1 при −5% сохраняется с вероятностью 95%; при неудаче результат равен 0, труд потрачен, исходное сырьё и деньги возвращаются. Выпуск 20 при −5% даёт 19 без случайного броска. Для частично потерянной партии возврат пропорционален потере; неделимые затраты округляются так, чтобы оставшийся выпуск оплачивал необходимое целое сырьё. Положительный дробный бонус новых партий переносится между партиями одной линии и одного продукта: двадцать выпусков по 1 при +5% дают суммарно 21.

Чек переживает переход между десятниками и изменение рецепта. Возвращается фактически списанный материал, а не материал из нового рецепта. Возраст зарезервированных партий учитывается каждый период; возврат не освежает пищу и не обходит обычную порчу. ID партий в резерве защищаются от повторного использования и обычного объединения. Материал возвращается в исходное складское помещение без потери из-за переполнения; возможное превышение вместимости остаётся видимым в обычном учёте склада.

Старые уже оплаченные партии без чека завершаются по прежнему правилу: точный возврат по ним невозможно восстановить. Следующая партия получает чек и новое поведение. Миграция и запись данных мира вручную не выполнялись. Случайный результат рассчитывается в Preview; Apply использует подготовленное состояние и не выполняет повторный бросок.

## Ограничения и оставшаяся проверка

- Старые отчёты, в которых политические поля никогда не сохранялись, невозможно достоверно восстановить. Новые отчёты и пакеты сохраняют их.
- У старой системы с утраченной хроникой нельзя восстановить точную дату последней смены. Сохранившиеся акты используются при нормализации; выбранная недефолтная система не получает повторный бесплатный выбор. Будущие изменения сохраняют устойчивые метаданные.
- Старую оплаченную производственную партию без чека нельзя безопасно отменить с точным возвратом. Действие блокируется с объяснением; партию нужно завершить. Это исключает выдуманное сырьё и дублирование.
- Пакет с более чем 40 событиями отклоняется до записи, чтобы сохранить каждое доступное решение. Его следует разделить на меньшие пакеты.
- Проверка игрового баланса сочетаний и живая проверка интерфейса/сокетов Foundry остаются ручными. Автоматические выборы, фракции и исходы восстаний относятся к отдельным будущим механикам v1-контракта, а не к текущему списку исправлений.

## Проверка в Foundry после исправлений

1. ГМ: включить/выключить каждое право; проверить реальные player-клиенты и кнопку «вид игрока» при открытой/приостановленной Политике. Административные формы должны оставаться только у ГМа; проверить вкладку, прокрутку и фокус в Foundry 13/14.
2. Игрок: петиция в протекторате, директива при выданном праве, указ по хартии с одобрением. До одобрения оплаты нет; после изменения казны/прав заявка проверяется заново. Отклонение содержит публичную причину.
3. Сокет: без активного ГМа окно только для чтения; смена authority-GM и повтор после таймаута сохраняют ID и не повторяют оплату. Одновременное изменение владения вызывает обновление устаревшего окна.
4. ГМ: оплаченные «Сведения» → запрос игрока → публичный ответ → однократное использование, в том числе при приостановке. Отмена указа требует причины и не сбрасывает перезарядку. Открытие/разрешение восстания записывается в историю.
5. Представитель: предупреждение за два периода, истечение, переизбрание; смерть/перенос. Изменить слоты/срок системы в редакторе, проверить остановку эффекта закрытого слота и сохранение цены/паузы после длинной хроники.
6. Производство: предыдущий полный/неполный рацион, +5% на мелких партиях, −5% и сырьё неудачных единиц. Отмена партии/удаление линии возвращает исходные ресурсы, деньги и возраст; повтор не дублирует возврат. Проверить переполненный склад и старую партию без чека. На ферме/в загоне проверить изменение труда при прежних биологических сроках.
7. Маршруты: доступный/недоступный УРС, транспорт и закрытая торговля. Содержание сети при выполненных/нарушенных условиях. Проверить текущие Репутацию, Контроль, оборону и УРС.
8. Preview 3 десятников → Apply → повтор Apply → открыть сохранённый отчёт. Проверить оплату, дань, питание, истечение указов и доступность события раннего периода при тихом последнем. Повторный Apply не списывает деньги и не перебрасывает результат. Эти проверки выполняет пользователь.
