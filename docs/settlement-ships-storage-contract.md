# Корабли: предложение структуры данных и интеграции

**Исторический контракт ранних этапов.** Актуальный продуктовый контракт, статус и очередь работ — в [основном плане кораблей](settlement-ships-implementation-plan.md), обновлённом 13 сентября. Реализованное дополнение хранения — [мировые маршруты, сметы и присутствие экипажа](ships-world-stage.md). Прежние рейсы ниже сохраняются для совместимости; новые корабли подключаются к мировой модели явной командой ГМ. Будущие поля в таблицах ниже не означают их наличия в коде или согласования новых расширений хранения.

Обновлено: 2026-09-10. Статус: расширение согласовано пользователем. К ручному рейсу добавлен [этап предложений и случайных итогов](ships-contracts-stage.md) в той же коллекции. Таблицы ниже сохраняют целевой контракт полной механики; физический груз, попутный заказ и ремонт как состояние ещё не подключены.

## Размещение

Добавить `holding.special.ships` в существующий документ владения внутри `skyholdHoldings`. Новые world settings не вводить. Общая казна остаётся только в `holding.storage.moneyCopper`; её копию в корабле не хранить. Действующие `special.notes`, `special.list` и `special.market` сохраняются.

Коллекция:

```js
special.ships = {
  list: [],                 // корабли
  offers: [],               // действующие предложения
  offerPeriod: null,        // последний зафиксированный период обновления
  history: []               // компактные итоги завершённых рейсов
};
```

Один корабль:

| Поле | Назначение |
|---|---|
| `id`, `name` | Устойчивый ID и редактируемое название |
| `commanderRef`, `coCommanderRefs` | Ссылки на Элину и доверенных командиров, без копий Actor |
| `crewRefs` | Ссылки на подтверждённых членов команды; обязательный источник ID для будущего импорта |
| `crewTarget` | Предлагаемый штат 36; не создаёт отсутствующих людей автоматически |
| `speedKmPerDay` | 150 для «Магнифика»; целые километры в день, без ночной фазы |
| `capacityLoadPoints`, `hiddenCapacityLoadPoints` | Вместимость в существующих целых points; тайники входят в общий предел |
| `condition`, `traits` | Состояние и согласованные особенности; лёгкое вооружение как характеристика, без тактического боя |
| `status` | `docked`, `away`, `repairRequired` |
| `onboardCopper` | Неотрицательное целое число медных монет; в поселении 0 |
| `attentionByDirection` | Значение 0–10 и последний период снижения по устойчивому ID направления |
| `activeVoyage` | `null` либо единственный активный рейс |

500 тонн пока являются лорным ориентиром: не приравнивать тонну к point без калибровки канонической нагрузки. Конкретный перевод определить в этапе экономики; до него нельзя считать корабль готовым к отправке реального груза.

Рейс:

| Поле | Назначение |
|---|---|
| `id`, `departureOperationId` | Устойчивые ключи рейса и однократной отправки |
| `directionId`, `routeSnapshot`, `orderSnapshots` | Направление, согласованный маршрут, основной и попутный заказы |
| `startedAtQd`, `lastProcessedQd` | Начало и последний обработанный прогресс; фаза суток не нужна |
| `legs`, `progress` | Полёты/портовые работы, оставшийся путь и время; задержки изменяют оставшуюся часть |
| `cargo` | Ссылки на товары/предметы, количество, принадлежность груза и сохранённая оценка |
| `style`, `attentionAtDeparture` | Зафиксированные условия отправки |
| `ledger` | Переводы, подготовка, выручка, реальные расходы; только операции этого рейса |
| `eventState` | Ожидающее решение и идентификатор однократного разрешения |

Скрытые броски, тайны ядра и NPC хранить в существующей области данных ГМ или за отдельным проверенным механизмом приватности. Простое скрытие HTML не обеспечивает тайну. До подключения информации проверить доступность split-settings игрокам; случайный seed нельзя передавать клиенту, если он раскрывает будущий исход.

В этапе случайных дел будущие броски вообще не сохраняются: authority-GM создаёт их только при защищённом подведении итога. В рейсе сохраняются уже раскрытый результат и признак применения; при недостатке средств результат остаётся прежним. Снимок предложения отделён от изменяемого времени задержки. `offers` и `offerPeriod` используются для подборки текущего игрового периода, без отдельного world setting. Автоматическое снижение внимания по периоду пока не реализовано.

## Операции и права

Добавить независимое разрешение `holding.gm.playersCanManageShips` со значением false по умолчанию. Оно разрешает корабельные операции с деньгами/грузом в рамках их валидаторов, но не даёт произвольного редактирования казны и склада. `playersCanEditSpecial` не предоставляет управление кораблём.

Игрок передаёт intent через существующий authority-GM socket: `holdingId`, `shipId`, `operationId`, ожидаемую revision и только параметры действия. ГМ заново читает актуальную казну/склад, проверяет права и условия и выполняет `SkyholdData.transaction`. Из клиента не принимать готовый итоговый баланс или результат броска.

- **Создание/редактирование корабля:** ГМ; activeVoyage и деньги не редактируются обычной формой характеристик.
- **Отправка:** резерв корабля, снятие груза со склада, перевод бюджета и расходы подготовки в одном commit.
- **Решение события:** проверка его ID, доступных вариантов, бортового баланса и актуальной revision.
- **Ремонт:** отдельная операция с понятной ценой; в пути платит борт, дома общая казна.
- **Продвижение/возвращение:** существующий десятник; snapshot, stale check и однократное применение. Возвращение переводит остаток в общую казну и груз на склад вместе с завершением рейса.

Применять общий command-result protocol и существующий слой idempotency. Локальный расчётный журнал не заменяет проверку revision и операционную защиту мира. Не хранить бесконечный второй общий журнал receipts: после завершения компактный итог переходит в историю, а поздние повторы блокируются протоколом и терминальным статусом рейса.

## Совместимость и активация

Старое владение без `special.ships` отображается как пустое. Добавление пустой коллекции при согласованной нормализации не создаёт корабли, не исправляет Actors и не списывает средства. Создание «Магнифика» и импорт экипажа — отдельное действие ГМ после предварительного просмотра. Для текущих аддитивных defaults schema version сохранена; commit-marker recovery не изменялся.

## Что уже реализовано вне мира

- `scripts/engines/ships/voyage.js`: чистый расчёт расписания и проекция прогресса. Скорость 150 км в день. Длительность хранится в QD, без остановки на ночь; портовые работы прибавляют только свой срок. Нулевые участки допустимы, отрицательные/дробные внутренние единицы отклоняются.
- `scripts/engines/ships/funds.js`: независимая неизменяющая вход модель перевода бортового бюджета, расходов, выручки и возвращения. Это тестовая расчётная форма, **не предложенная копия баланса поселения в world storage**.
- `npm run ships:check`: независимость от фазы суток, перебор расстояний и портовых задержек с независимой пошаговой моделью; финансовый пример 1000 → 1070, недостаток средств, переполнение, повтор и конфликт ID.

Реализованы пустая коллекция `special.ships`, безопасная нормализация и карточки ГМ. `routePlan` хранит назначение, расстояние в одну сторону, дни в порту, подготовку, содержание в день и плату за рейс. Отправка фиксирует смету в `activeVoyage.quote`; последующее изменение плана не переписывает принятые условия. Маршрут этого этапа: туда, стоянка, обратно.

`scripts/engines/ships/runtime.js` выполняет отправку, ручной расход/поступление и продвижение на копии владения. При отправке общая казна оплачивает подготовку и переводит бюджет на борт; плановое содержание всего рейса сразу оплачивается из этого бюджета. Остаток служит резервом. Это денежная абстракция снабжения, без топлива и без движения ресурсов склада. Дополнительные расходы и поступления в пути проводит ГМ с обязательной причиной. При нехватке денег операция целиком отклоняется.

`scripts/apps/ship-operation-executor.js` использует существующую транзакцию владения и журнал `ship-operation`. Проверяются права, отображённая пользователю revision, ID рейса и подпись повтора. `scripts/data/ship-socket.js` подключён к общему сокету и command-result: игрок отправляет intent через authority-GM, повтор после таймаута сохраняет operationId. Разрешение `gm.playersCanManageShips` по умолчанию выключено и открывает игроку отправку подготовленного ГМ рейса и подведение его случайного итога. Генерация ручных предложений и произвольные денежные операции остаются у ГМ. В мировой модели это разрешение также открывает игроку первое получение местных предложений через authority-GM; переброс существующей доски остаётся командой ГМ. Общие player patches к кораблям по-прежнему запрещены.

В `finance/economy-domain.js` рейсы продвигаются на snapshot после рыночных доставок, до финансирования периода. Возвращение начисляет плату один раз, переводит весь остаток в поселение и завершает рейс в том же результате. Это граница расчёта периода, а не посуточная симуляция трат поселения. Предпросмотр не пишет в мир; применяется существующая защита десятника от stale и повторного commit. В change set есть группа кораблей, история хранит до 100 рейсов, карточки показывают последние 10. Перевод остатка помечен как внутренний, отдельно от чистого результата рейса.

`ships:check` дополнен проверками транзакций, прав, конкурирующих отправок, повторов, смены authority-GM, замороженной сметы, возврата до финансирования периода и сохранения истории десятника. Проверки runtime включены в `suite:storage`, расчёты контрактов — в `suite:economy`. Расчётное ядро загружается лениво. Предложения, случайные исходы и внимание 0–10 используют тот же путь сохранения; реальные ресурсы, автоматическая география и импорт команды ещё не подключены. [Ручная проверка](ships-manual-smoke.md) выполняется пользователем в Foundry.

Аддитивные defaults не требуют разрушительной миграции: schema version не менялась, старые данные дополняются пустой коллекцией при обычной нормализации. Поле cargoTonnes служит лорной характеристикой; capacityLoadPoints остаётся null до калибровки, поэтому готовность к перевозке из него не выводится.
