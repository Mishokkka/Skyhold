# Исходные нормы технического обслуживания

> Статус: входная таблица `building-maintenance-proposal-check.mjs` для подготовки v15. Путь сохранён ради потребителя. Нормы используются в последующих каталогах; текущая активация и занятость определяются [экономикой](economy-contract.md) и [трудом](labor-contract.md), применение — [отдельным переходом](migrations.md).

Денежное содержание, эксплуатация функции и технические QD — разные расходы. Для объектов вне таблицы отдельная техническая норма равна 0; это не отменяет денежное содержание. Версия `maintenance.schemaVersion = 2` хранит прямые QD в существующем `requiredPoints`; версия 1 означает прежние очки. Нормальная загрузка не переключает сохранённое здание между ними.

Технический труд оплачивается по назначению, не занимает производственное место и не создаёт вторую эксплуатационную плату. Норма засчитывает оплаченные обычные слоты без бонуса эффективности. После простоя основная работа ждёт выполненной технической проверки. Неоплата не обнуляет прежний backlog; автоматического разрушения нет.
