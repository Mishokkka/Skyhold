# Два режима труда и распределение по линиям: проверка перед реализацией

Дата: **20 октября 2026 года**. Статус: проверка реализуемости завершена; новая механика, новый формат хранения и миграция **не внедрялись**. Мир Foundry не изменялся.

Этот документ фиксирует выбранное после предыдущего аудита направление. [Проект полного перехода на QD](unified-labor-system-design-2026-10-15.md) больше не является планом внедрения целиком. [Обнаруженные ранее проблемы](labor-transition-review-2026-10-16.md) сохраняют значение там, где затрагивают нынешний расчёт.

## Вывод

**Систему можно реализовать на существующей основе.** Можно сохранить окно планировщика, расчёт рецептов, состояния партий, общий личный бюджет, финансовые обязательства и передачу действий игроков ГМу. Переписывать строительство или всю экономическую хронологию не требуется.

Но нынешние постоянные назначения и назначения QD ещё не образуют два законченных режима зданий. Переключения между линиями после достижения результата также нет. При попытке добавить только элементы интерфейса постоянное назначение будет потеряно, некоторые новые настройки исчезнут при загрузке, а время и оплата окажутся несогласованными.

Дополнительно воспроизведены две ошибки расхода рабочего времени. Их устранение входит в обязательную подготовку реализации, а не в необязательное улучшение.

Это вывод о реализуемости и необходимых работах. Работоспособность ещё не написанной системы этим не утверждается.

## Принятые исходные правила

- **Постоянный штат:** сотрудник закреплён за одним зданием на весь десятник. У него нет доступного внешним заданиям остатка QD, даже если в здании возник простой.
- **Работа по заданиям:** житель выделяет конкретным линиям определённые QD; остаток можно распределить между другими работами.
- Режим относится к зданию и задаётся ГМом. Для первого варианта у здания один режим. Пассивный объект обходится без назначения работников.
- У штатного сотрудника есть основная работа и одна необязательная дополнительная работа того же здания. Это не два независимо оплачиваемых полных назначения.
- **Оплата постоянного сотрудника согласована:** одна заранее установленная ставка для всех его работ в этом здании. Переключения и вынужденный простой её не меняют; за один рабочий интервал оплата начисляется один раз. Для QD-заданий сохраняются ставки соответствующих работ.
- Количество фамилий ограничивает постоянный штат. Для режима QD согласовано ограничивать объём труда/работы и оборудование, а не обещать точный предел одновременно присутствующих людей без расписания.
- Обязательное ежедневное обслуживание, квалификация, разрешение сверхурочных и добровольного труда сохраняются.
- Стройбригада остаётся отдельной постоянной занятостью. Строительство выполняет попытку за десятник целиком; никакого вычисленного «третьего дня завершения» не вводится.
- Норма обычных гражданских QD остаётся настройкой ГМа 0–20. Значение нормы не меняет календарную продолжительность десятника.

## Как должны работать основная и дополнительная линии

### Дополнительную работу правильнее назвать резервной

Прежнее название «следующая задача» подходит только для окончательного завершения основной работы. При временном ожидании оно вводит в заблуждение: сотрудник может понадобиться на основной линии снова.

Предлагаемое уточнение: **основная работа имеет приоритет, резервная используется, когда основной не требуется или недоступен труд**. Это по-прежнему два назначения, без произвольной очереди.

| Состояние основной работы | Предлагаемое поведение |
|---|---|
| Можно выполнять полезную работу, цель ещё не достигнута | Работать на основной |
| Одна партия выдерживается, но есть место и условия подготовки следующей | Продолжать основную; наличие выдержки само по себе не означает простой |
| Все доступные места оборудования заняты ожиданием | Работать на разрешённой резервной |
| Нужен сбор готовой партии основной линии | Выполнять сбор в пределах общего бюджета; затем снова оценить доступные работы |
| На основной временно нет сырья | Можно выполнять заранее разрешённую резервную, не расходуя сверх согласованного времени и условий оплаты |
| Основная снова доступна | Возвращаться при следующем свободном рабочем QD |
| Общая цель основной линии достигнута | Продолжать резервную до конца периода; не открывать новые партии основной сверх цели |
| Резервной нет либо она недоступна | Оставаться в оплаченном простое по принятому договору; не появляться свободным работником поселения |
| Основная работа — действующее дежурство | Отсутствие клиентов не освобождает сотрудника для резервной работы |

Переключение происходит только на ещё не потраченном рабочем времени. Остаток повышенной производительности уже оплаченного целого QD нельзя выдать другой линии как новый QD. Подготовленная партия сохраняет свой прогресс при уходе человека; переключение не отменяет её и не возвращает сырьё.

Выбор задания должен происходить до выполнения соответствующего рабочего QD, независимо от порядка отображения линий. Иначе линия, стоящая ниже, получает преимущество: верхнюю уже обработали, а нижняя ещё может забрать переключившегося работника.

Это уточнение поведения предложено по результатам проверки. Оно не объявляется уже реализованным.

### Цель принадлежит линии, а не каждому её работнику

Если Анна и Борис совместно должны подготовить 20 ЕД., цель одна на двоих. Нельзя каждому выдать самостоятельное задание на 20 ЕД. или позволить обоим одновременно открыть последнюю необходимую партию.

Пример «две партии» из предыдущего ответа требует исправления. У нас уже есть частичная загрузка: партия может содержать и 1, и 30 единиц. Поэтому две партии не гарантируют определённого объёма товара.

Рекомендую для обычных рецептов цель **«подготовить X ЕД.»**, рядом с которой видно: сколько уже подготовлено, сколько ждёт выдержки и сколько готово к получению. Для линии без выдержки подготовка непосредственно даёт выпуск; для выдерживаемого товара она не означает немедленной готовности.

Необходимо сохранить следующие границы:

- цель проверяется перед каждым новым запуском, в том числе если сильный работник способен выполнить несколько циклов за один QD;
- ещё не завершённый выпуск уже зарезервированных партий учитывается при решении, можно ли начинать новые;
- действующая оплаченная партия не обрезается ради уменьшенной цели; её оставшийся труд и ожидаемый выход показываются отдельно;
- «запускать от X ЕД.», вместимость и фиксированная стоимость старта сохраняются;
- если остаток цели меньше допустимого запуска или рецепт не допускает дробления, программа объясняет несовместимость; не округляет объём и расходы вверх молча;
- для пользовательского случайного выпуска нельзя обещать точное количество заранее. Там остаётся трудовой предел и явное предупреждение о неопределённом результате; правило количественной цели требует отдельной проверки формулы;
- изменённая цель не должна перезапускать бросок выхода уже начатой партии;
- сбор готового результата — отдельная трудовая стадия, если у рецепта указана его стоимость. После достижения цели подготовки нельзя оставить всю линию без возможности сбора.

Нынешняя цель общего плана выражается только в QD и нужна подбору работников. Производственный расчёт не использует её как предел выпуска. Новый ограничитель результата действительно предстоит написать.

### Два назначения не покрывают автоматически все работы любого здания

У здания могут одновременно существовать приготовление товара, его продажа, обслуживание посетителей и техническая проверка. Два назначения одному человеку не должны незаметно выполнять четыре функции.

Для такого здания нужны разные сотрудники либо явный выбор выполняемых задач. Например, работа кухни трактира не заменяет работу зала. Техническая проверка, которая нужна до запуска оборудования, тоже должна получить исполнителя и время; её нельзя сделать бесплатной невидимой третьей задачей.

Первый вариант с основной и резервной работой намеренно ограничен. Если конкретному составу требуется больше работ, план должен показать незакрытую потребность. Не следует скрывать её обещанием автоматического универсального распределения.

## Оплата — согласованное решение

Для QD-заданий сохраняется прежний принцип: согласованное время оплачивается по соответствующей работе; вынужденный простой в пределах назначения оплачивается. Личная ставка и согласованный бесплатный труд сохраняются.

**Пользователь выбрал одну согласованную ставку постоянного сотрудника для всех его работ в этом здании.** Это решение относится к проектируемому постоянному штату; новая механика оплаты ещё не внедрена.

При назначении фиксируются ставка сотрудника и согласованный объём обычного/разрешённого сверхурочного времени. По ним можно заранее определить зарплатное обязательство. Основная работа, резервная работа и вынужденный простой в пределах этого назначения оплачиваются по той же ставке. Ставки отдельных линий не переоценивают работу штатного сотрудника.

Например, при ставке сотрудника 12 ММ в день и назначении 20 обычных QD зарплата составляет 120 ММ. Она остаётся 120 ММ, если часть этого времени он провёл на резервной линии со ставкой для QD-заданий 18 ММ или вынужденно простаивал. Это пример будущего штатного режима; приведённый выше результат 162 ММ описывает нынешний расчёт отдельных назначений по ставкам линий.

Выбранное правило позволяет сохранить предварительный расчёт зарплаты до производства. Фактические переходы нужны для учёта выполненной работы, расходников и эффектов услуг; пересчитывать зарплату по времени на каждой линии не требуется. Изменение ставки после подготовки прогноза делает его устаревшим.

За один рабочий QD нельзя одновременно начислить оплату резервной работы и простоя основной. Согласованный бесплатный труд остаётся отдельным явным условием; нулевая ставка сама по себе не считается подтверждением такой договорённости.

При сокращённой гражданской норме уменьшается доступный труд и его оплата по уже принятому принципу; постоянное закрепление всё равно запрещает внешнюю работу весь период. Служебные эффекты при этом нельзя автоматически считать полными только по фамилии в штате — ограничения, выявленные у медицины, складов и кадровой конторы, остаются существенными. Для них нужны свои подтверждённые условия обслуживания.

## Где именно нужно менять модуль

| Область | Что можно сохранить | Что необходимо добавить или изменить |
|---|---|---|
| Данные назначения | Существующие ссылки на жителя, здание и стабильный ID линии; строки QD для заданий | Режим здания; внутриштатное назначение основной/резервной работы; производственную цель и необходимые итоги исполнения |
| Планировщик | Окно, группировку зданий, поиск, компактный подбор, просмотр от жителя | Различать найм в штат, изменение работы внутри штата и изменение QD. Штатному показывать «занят весь десятник» |
| Проверка плана | Возраст, присутствие, ранения, закрепления, скрытые данные, исключения допуска ГМа | Проверку режима здания, запрет внешнего труда штатному, допустимость основной/резервной, отдельные пределы штата и объёма QD |
| Производство | Оплаченные партии, сырьё, прогресс, выдержку, вместимость, порчу | Выбор одной допустимой работы на следующий QD; общую цель линии; расход времени без повторного списания |
| Финансы | Обязательства, долги, порядок разрешения работ, личную ставку и добровольность | Подтверждённый договор штатного сотрудника и учёт вынужденного простоя без двойной оплаты |
| Услуги | Собственные эффекты и условия конкретных учреждений | Учитывать профильную работу, а не любое присутствие человека в здании |
| Сохранение игроком | Передачу ГМу, проверку прав, версии, повторов и целостности запроса | Разрешить только нужные новые поля; проверять их смысл на стороне ГМа |
| Переход существующих данных | Предварительный просмотр миграции и защиту начатых партий | Соответствие старых и новых линий для всех назначений и целей, обзор конфликтов режима |

Квалификация производства сейчас преимущественно оценивается по профилю здания. Нельзя уже сейчас обещать, что подбор различает любые профессии разных линий одной постройки. Для первого этапа применяются существующие допуски; где двум работам действительно нужны разные профессии, это должно быть явно отражено в настройках задач и проверено отдельно. Новые профессии не выводятся из названий линий.

Все способы назначения должны соблюдать одинаковые правила: окно плана, карточка жителя, список жителей, слоты здания, массовый подбор и специальные редакторы. Изменение только одного окна оставит обходы ограничения постоянной занятости.

Есть ещё два важных ограничения исполнения:

- Подтверждение услуг сейчас строится по назначенным оплачиваемым QD. После переключений его нужно строить по реально выполненной работе соответствующей функции, отдельно учитывая дежурство и оплаченный простой. Иначе зал трактира получит эффект за время, проведённое сотрудником на кухне.
- Поле получает доступный труд за период целиком. Автоматический переход «закончил посев — остаток времени отдал другой работе» нельзя подключить тем же способом, что обычную производственную линию, пока расчёт поля не возвращает достоверный использованный труд и допустимые моменты его выполнения. Это задача отдельного подключения на этапе 4, а не готовая возможность нынешнего кода.

Прогноз и проведение должны использовать одинаковый выбранный план и сохранённый результат подготовки. Повторное вычисление случайного выпуска при нажатии «Применить» не допускается: иначе изменится и момент перехода сотрудника. Смена нормы, ставок, состава, режима или партий после прогноза делает его устаревшим.

## Что показала проверка каталога

В текущем стандартном каталоге **126 шаблонов, 79 производственных линий с источником «работники»; 23 шаблона имеют больше одной производственной линии**. У 6 шаблонов найдены линии с положительным `waitDays`, у 6 — с положительным `batchCapacity`. Это инвентаризация полей текущего каталога, не проверка всех пользовательских рецептов или уже построенных экземпляров.

Чистых источников `time` и `content` в этом перечне стандартных линий нет, но движок их поддерживает. Производства с трудом и последующим ожиданием при этом существуют: отсутствие `source: time` не означает отсутствие выдержки.

Для каждой постройки до перехода нужна небольшая предметная запись:

1. Режим: постоянный штат, QD-задания или пассивный объект.
2. Какие работы действительно существуют; какие дают самостоятельную услугу, а какие являются стадиями одной партии.
3. Чем ограничен объект: штат, труд за период, вместимость партии или оборудования.
4. Какие работы требуют ежедневного выполнения или непрерывного дежурства.
5. Может ли сотрудник перейти между выбранными работами и сохраняется ли его допуск.

Режим нельзя безопасно вывести из старых `workersMin`/`workersMax`. Для QD-предела также нельзя молча перемножить прежний максимум на новую личную норму и объявить результат обоснованной производительностью. Отдельно сохраняется уже согласованная пассивность обычного колодца.

## Сохранение и переход старых назначений

Нынешний старый список работников похож на список штатных мест. Для постоянного штата это полезная основа. Для QD-заданий его нельзя использовать как полный список всех последовательных исполнителей: подгонка массива под максимум способна удалить лишних людей или увеличить сам максимум.

Новый формат должен явно разделить четыре вещи: режим здания, его постоянных сотрудников, задачи этих сотрудников и обычные назначения QD. Основную и резервную нельзя хранить как два полных бюджета. Расписание выбранных действий и фактический отчёт должны вычисляться из одного и того же принятого плана.

Отдельный список конфликтов нужен как минимум для таких ситуаций:

- у человека есть QD в двух зданиях, а одно становится штатным;
- постоянный сотрудник был назначен зданию с несколькими линиями, но явно не выбирал основную;
- выбрана удалённая или заменённая линия;
- несколько старых линий неоднозначно соответствуют новой;
- изменён режим здания с активными заданиями или незавершёнными партиями;
- превышается новый предел штата либо труда;
- ГМ изменил ставку, норму QD, допуск или режим после подготовки прогноза.

Перестановка или переименование линии не меняет назначения: используется её постоянный ID. При замене ID одновременно обновляются ссылки QD, основных/резервных работ, целей и закреплений. Неоднозначное соответствие показывается пользователю.

Для этого действительно потребуются новые сохраняемые сведения. [AGENTS.md](../AGENTS.md) прямо требует: «Do not add production dependencies or change the storage format without explicit approval». Ранее было одобрено хранение общих целей и закреплений; оно не описывает новые режимы и внутриштатные назначения. Этот обзор обосновывает необходимость и содержание нового хранения, но не меняет его. Конкретную схему следует предъявить на согласование перед внедрением. Подготовка миграции не является разрешением применить её к миру.

## Предлагаемый порядок реализации

**Этап 1 — исправить общий расход времени и закрепить проверками согласованную оплату.** Неудачная неделимая операция либо вообще не списывает труд, либо сохраняет выполненную часть по явно установленному правилу. Получение сырья и производство расходуют один общий бюджет; после получения сырья остаток проверяется повторно. Незаметное введение частичного прогресса сбора не требуется: для первого исправления достаточно проверки доступного полного объёма до списания. Для постоянного штата проверить единую ставку при переходах и простое, для QD-заданий — ставки соответствующих работ.

**Этап 2 — добавить два режима без автоматических переходов.** Сначала один штатный сотрудник с одной основной работой, настоящий запрет внешних назначений, правильная оплата и сохранение. Параллельно сохранить QD-задания и разделить их ограничение с числом штатных мест. Это промежуточная проверка, не объявление всего запроса выполненным.

**Этап 3 — подключить общую цель линии и резервную работу.** Проверить частичные партии, возврат с резервной, сбор, порядок строк, общие цели нескольких работников и отсутствие двойной оплаты. Не добавлять произвольную очередь задач или автоматическое увеличение найма.

**Этап 4 — подключить остальные реальные работы зданий.** Уход, посев, услуги, техническое обслуживание получают свои условия доступности и завершения. Уже существующие периодные механики сохраняются. Бой, строительство, прибытие груза и смена сезона не переводятся попутно на выдуманное общее расписание.

**Этап 5 — проверить шаблоны и переход пользовательских данных.** Сначала предварительный просмотр и сравнение расчётов на копиях; применение мира — только отдельной разрешённой операцией. Без определения режима и назначения линий для затронутых шаблонов переход нельзя считать завершённым.

## Обязательные проверки реализации

| Группа | Что должно быть доказано |
|---|---|
| Постоянное назначение | Редактирование линии не увольняет человека; простой не даёт внешнего свободного времени |
| Все входы редактирования | Через карточку, слот, массовое действие или запрос игрока нельзя получить несовместимые назначения |
| Сохранение | Режим, основная, резервная и цель переживают закрытие окна, перезагрузку и обычную нормализацию |
| ID линий | Переименование и перестановка сохраняют назначения; удаление создаёт понятный конфликт |
| Резервная работа | Переход только на непотраченном времени; возврат к основной; недоступная резервная не создаёт третью работу |
| Дежурство | Отсутствие пациентов или посетителей не освобождает человека автоматически |
| Общая цель | Двое работников не удваивают цель; сильный работник не открывает лишние партии внутри одного QD |
| Начатая партия | Изменение цели/сотрудника не обрезает выход, не возвращает сырьё и не перебрасывает сохранённый результат |
| Частичная загрузка | Соблюдаются минимум старта, вместимость, постоянные расходы и достижимость выбранного количества |
| Выдержка | Свободный человек не означает свободное оборудование; ожидающие партии не замораживаются из-за переключения сотрудника |
| Получение сырья | Нет частичного безрезультатного списания и отрицательного остатка бюджета |
| Норма и сверхурочные | Проверены 0, 1, 7, 16, 19, 20; чужие часы не появляются; сверхурочные отдельно разрешены |
| Деньги | Единая ставка штатного сотрудника сохраняется при переходах и простое; ставки QD-заданий, личная ставка, добровольность и нехватка денег учитываются без двойной оплаты |
| Услуги | Кухня не считается работой зала; случайное присутствие не даёт полной медицинской/складской услуги |
| Животные и поля | Уход проверяется по дням; рост не занимает руки; нельзя направить труд на ещё недоступный этап |
| Несколько десятников | План повторяется корректно; цели периода не дублируют начатые партии; прежнее расхождение длинного расчёта устранено |
| Права и повторы | ГМ и игрок видят допустимое; повтор запроса не удваивает запись или оплату; старый прогноз отклоняется |
| Миграция | Нет тихой потери изменённых рецептов, ставок, ролей, ссылок и незавершённого труда |
| Масштаб | Подбор и просмотр проверены на 20, 50, 100 и 200 жителях с несколькими линиями |
| Foundry | Оба режима проверены в окне ГМа и игрока, включая стили, сохранение состояния, открытые окна и совместимость 13/14 |

Последние проверки в живом Foundry остаются за пользователем, если отдельно не делегированы. Проверки Node не доказывают внешний вид и все события приложения.
