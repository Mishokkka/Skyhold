# Формат мира, обновления и восстановление

Модуль открывает миры со схемой `v72` и каталогом зданий `v19`. При открытии он выбирает сохранённую ревизию с учётом восстановления после сбоя, проверяет версии, затем нормализует данные в памяти. Применение обновлений и импорт Actors требуют отдельного действия ГМа.

Для более старого формата откройте **копию мира** на [прежней версии Skyhold с миграциями](https://github.com/Mishokkka/Skyhold/tree/830a292f97d0357cada3df02676a51746321f416) и завершите переход на `v72` / `v19` перед обновлением модуля. Несовместимое сохранение вызывает ошибку при открытии окна и остаётся без записи.

## Разделение операций

| Операция | Смысл |
|---|---|
| Нормализация при чтении | Заполнение значений по умолчанию в актуальном формате с сохранением пользовательских настроек |
| Явное обновление (Preview → Apply) | Изменение каталога и рецептов после подтверждения ГМа |
| Ремонт / reset | Явная ручная операция с названными последствиями и предварительной резервной копией |

## Каталог зданий (v19, 126 шаблонов)

- Окно «Обновить каталог зданий» готовит Preview замены дерева и параметров на текущий `v19`. При подтверждении модуль проверяет ревизию и содержимое, создаёт снимок отката и защищает операцию от повторной записи.
- «Обновить всё дерево и постройки» заменяет механические параметры шаблонов и удаляет дополнительные шаблоны. Имена, заметки, жители, имущество, казна, состояния и доля прогресса стройки сохраняются. Несовместимые незавершённые циклы, небезопасные резервы и постройки без соответствующего шаблона блокируют запись.
- При полной замене Preview показывает, кому освободятся QD общего обслуживания. Назначения обслуживания конкретных зданий сохраняются.

## Рынки, перевозки, корабли и контент

- **Общие рынки:** общие stock/demand хранятся в `meta.sharedMarkets` и активны по умолчанию для всех поселений мира. Если в сохранении `v72` / `v19` объект `meta.sharedMarkets` отсутствует или имеет `enabled !== true`, при загрузке и сохранении выполняется автоматический перенос локальных `holding.special.market.stock` и `demand` (включая активные брони спроса) и расчёт `clockTenday` по датам владений: для одного поселения переносится его текущее состояние и прогресс восстановления, для нескольких поселений `baseStock` / `baseDemand` берутся по максимуму, израсходованные остатки и брони объединяются под общим `clockTenday`. После активации (`enabled: true`) источником правды служит `meta.sharedMarkets`.
- **Незавершённые заказы прежней версии рынка:** автоматически в v2 не переводятся; завершите/отмените их до обновления либо сверьте в «Перевозки → Незавершённые заказы прежней версии» (список только диагностический; не перезаписывайте рабочий мир старым снимком поверх новых записей).
- **Расхождения груза и снесённые кладовые старых версий:** если проведение v2 сообщает об изменившемся грузе или осиротевшей строке снесённой кладовой, сверьте ID заказа/строки/партии и возраст с резервной копией до ручной правки (совпавший ID другого материала не подтверждает наличие груза).
- **Корабли, content packs и «Магнифик»:** старые клиентские договоры кораблей исполняются по прежним условиям; обычный content pack не удаляет отсутствующие строки ([формат](content-pack-format.md)); добавление команды «Магнифика» — отдельная GM-операция без World Actors ([инструкция](magnifique-crew-import.md)).

## Split-storage и восстановление

- Состояние разделено на `skyholdMeta`, `skyholdHoldings` и `skyholdCatalog`. `skyholdData` хранит цельный снимок для восстановления. Маркер завершения записи и хеши разделов позволяют определить, какую ревизию открыть после сбоя.
- При сбое записи или потере ответа сначала используйте проверку результата / повтор того же `operationId`, а не новую денежную операцию. Обмены с Actor/Item используют проверки владения и компенсацию; при неопределённом исходе ГМ сверяет склад и оба инвентаря по указанному ID операции.
- Код обновления зданий находится в `scripts/workflows/buildings/`. За выбор состояния отвечают `scripts/data/split-storage.js`, `storage-commit.js` и `storage-format.js`. Проверки выполнены сценариями `building:migration:check`, `suite:storage`, `storage:batch:check` и `hybrid:check`. Для ручной проверки используйте [общую матрицу](manual-foundry-smoke-matrix.md).
