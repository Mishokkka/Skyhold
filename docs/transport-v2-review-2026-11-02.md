# PR #13: исправления трёх замечаний и итоговая проверка

Проверена опубликованная версия `370987f969f1669ac4412a537ab63d0c9cc8973c` относительно `main` (`1d7dd80defe192ad4a9ccf1acde84a23fa4c5cac`): 121 изменённый файл. Дерево опубликованного коммита совпадает с локальным деревом, на котором прошли проверки. Этот отчёт добавляется следующим коммитом без изменения рабочего кода.

## Три исправления

| Замечание | Причина | Результат |
| --- | --- | --- |
| [Покупка своим кораблём при ограничении УРС](https://github.com/Mishokkka/Skyhold/pull/13#discussion_r4438081907) | Старый наёмный маршрут исключал товар ещё до расчёта собственного судна. | Выбор товара отделён от выбора транспорта. Рыночное окно использует минимальную региональную стоимость доступа; исполнитель проверяет УРС всей выбранной цепочки вместе со сложностью товара. |
| [Уточнение после исчерпания поиска](https://github.com/Mishokkka/Skyhold/pull/13#discussion_r4438081912) | Выбор участков и исключение перевозчиков отображались только при уже найденном плане. | Окно получает доступные услуги даже после неудачного поиска. Можно закрепить участок, исключить компанию и повторить расчёт. Подтверждение остаётся недоступным без допустимого плана. |
| [Замедление из-за истории](https://github.com/Mishokkka/Skyhold/pull/13#discussion_r4438081917) | Каждый расчёт хешировал подробности всех старых заказов; окно готовило все карточки. | Полностью завершённая история исключена из проверки актуальности расчёта. Карточки истории выводятся по 20; текущие обязательства видны на каждой странице. История сохраняется полностью. |

Склад, деньги, права, бортовой кошелёк, общая бронь, действующие договоры и незавершённые расчёты остаются частью проверки актуальности. Отдельная проверка ревизии также сохранена. Формат сохранения и работа с данными мира этой правкой не менялись.

Регрессионные сценарии проходят обычный путь GM/player: товар в окне рынка → расчёт → подтверждение у ведущего → исполнение → повтор команды и загрузка сохранённых данных. Для большого графа проверены реальные обработчики выбора участка и подтверждения; недопустимый наёмный путь, недостаточный УРС и превышение запаса по-прежнему отклоняются.

Старый исполнитель покупки допускает только повтор уже сохранённого результата; его историческая реализация используется лишь тестами. |

При дополнительной проверке обнаружен и исправлен ещё один дефект: на большой карте нужный порт мог пропасть из смешанного маршрута. Сначала бралось 24 точки по порядку каталога, поэтому несвязанные порты вытесняли полезную пересадку; результат ошибочно сообщал об отсутствии перевозки без указания лимита.

Теперь до ограничения отбираются публичные открытые порты, которые могут войти в цепочку по связности и минимальной стоимости УРС. Отбор использует нижнюю оценку без ограничения способов движения; окончательная проверка маршрута по-прежнему проверяет реальные воздушные связи, перевозчиков, груз и суммарный УРС. Оставшиеся точки упорядочены по этой оценке и идентификатору. Закреплённые участки, подтверждаемый план и порт, выбранный в новом поле «Учитывать порт при поиске», получают приоритет перед автоматическим отбором.

Лимит 24 точек для собственного корабля сохраняется. Окно сообщает о неполном переборе, позволяет выбрать пропущенный порт даже без найденного плана и отдельно показывает исчерпание поиска наёмных связей. Выбор порта добавляет его в расчёт; обязательный проход через него задаётся закреплениями участков. Порядок локаций и несвязанные порты проверены для покупки и продажи, ГМ и игрока, включая подтверждение, исполнение, повтор команды и нормализацию.

Выводы относятся к коду и автономным проверкам, а не к работе интерфейса в запущенном Foundry.
