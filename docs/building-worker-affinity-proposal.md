# Допуски, типажи и эффективность работников зданий

Дата: 2026-09-01.

Статус: справочник допусков и эффективности базового каталога, источник генератора профилей. Он содержит 118 профилей дерева и два сюжетных профиля. Наличие профилей в коде не означает, что сохранённый мир уже перенесён. В v15 добавлен профиль Дома собраний из редакции подготовки; полный состав отражён в [актуальном каталоге](building-catalog.md); загрузка не должна подмешивать новые механические требования в старые шаблоны.

## 1. Вердикт по полю «Осн. хар.»

До schema 70 `workerPrimaryAttribute` влияло на расчёт скрыто и избыточно. Оно автоматически добавляло к явно выбранным «Эффективным типам» ещё одно широкое условие «Все с СИЛ/ЛОВ/РАЗ/ЭМП». Если для него не был задан отдельный модификатор, работник получал стандартные `+0,5` эффективности.

Например, при «Осн. хар. = Сила» и видимых плашках «Все с ЭМП» и «Переговорщик» старый код дополнительно считал эффективными все типажи, содержащие СИЛ 5, хотя этой плашки пользователь не видел.

Решение реализовано: **«Осн. хар.» удалено из исходного каталога, экземпляра здания, нормализации и редактора**. Старые свободные строки типов и дробные карты коэффициентов также удалены. Шаблонно связанные здания получают утверждённый структурированный профиль; старое опасное назначение, не проходящее новый жёсткий допуск, сохраняется как явный GM-допуск без бонуса квалификации.

## 2. Что такое типаж жителя

Типаж — производная от характеристик, а не профессия:

| Характеристики `5+` | Типаж |
|---|---|
| нет | Разнорабочий |
| СИЛ | Силач |
| ЛОВ | Ловкач |
| РАЗ | Умелец |
| ЭМП | Переговорщик |
| СИЛ + ЛОВ | Строитель |
| СИЛ + РАЗ | Механик |
| СИЛ + ЭМП | Бригадир |
| ЛОВ + РАЗ | Ремесленник |
| ЛОВ + ЭМП | Посыльный |
| РАЗ + ЭМП | Управленец |
| СИЛ + ЛОВ + РАЗ | Мастеровой |
| ЛОВ + РАЗ + ЭМП | Агент |
| СИЛ + РАЗ + ЭМП | Старшина |
| СИЛ + ЛОВ + ЭМП | Полевой вожак |
| все четыре | Мастер на все руки |

Код использует порог `>= 5`, поэтому характеристика 6 также считается выдающейся. Обычный генератор с текущим бюджетом не может создать типаж с тремя или четырьмя характеристиками `5+`; они остаются допустимыми только для вручную созданных и импортированных жителей.

Типаж не доказывает специальность. «Умелец» не становится врачом, «Механик» — шахтёром, а «Переговорщик» — жрецом. Однако отдельное поле профессии дублирует социальное прошлое, создаёт противоречивые сочетания и не объясняет, как житель получил опыт. Поэтому поле `skill` удаляется из модели жителя. Профессиональная пригодность определяется только сочетанием **прошлого, характеристик и черт**.

Поле `role` остаётся, но не является профессией: это подпись текущего назначения (`Солдат`, пользовательская работа, служебное состояние). Источником фактической занятости остаются `workAssignment` и явный план QD; `role` не даёт производственного бонуса.

Прошлое отвечает на вопрос «что этот человек уже делал до поселения» и никогда не становится жёстким запретом само по себе. Подходящее прошлое даёт производственной работе ровно `+10%`; несколько совпадений не складываются. Черта описывает особое качество или приобретённую подготовку. Одна подходящая положительная рабочая черта даёт ещё `+10%`, одна мешающая — `-10%`; учитывается не более одной положительной и одной отрицательной черты. Особые черты `Builder` и `Чудотворец` работают по собственным правилам и не дают универсальные `+10%`.

### Селекторы таблицы

- `СИЛ`, `ЛОВ`, `РАЗ`, `ЭМП` — любой типаж, содержащий соответствующую характеристику 5+.
- `СИЛ&РАЗ` и аналогичные пары — типаж содержит обе характеристики; тройные и универсальный типы также подходят.
- `РР*` — не любой «Разнорабочий», а сбалансированный: ни одной характеристики 5+, каждая не ниже 3, сумма не ниже 13. Это не позволяет слабому жителю `1/1/1/1` получать бонус за одно лишь отсутствие специализации.
- Если житель одновременно подходит под `+25%` и `+50%`, применяется только лучший бонус.

## 3. Допуск, опыт и ожидаемый штат

У здания различаются пять независимых вещей:

1. `workersMin` — сколько разных живых, трудоспособных и оплаченных людей требуется. Эффективность не заменяет головы.
2. Допуск — минимальные характеристики каждого назначенного работника. Он применяется только там, где без него работа физически невозможна или опасна.
3. Профильное прошлое — явно заданная для шаблона группа прежних занятий. В производстве оно даёт работнику `+10%`, но не запрещает работу остальным.
4. Рабочие черты — явно заданные для шаблона положительные и отрицательные черты. Они меняют только производственную работу либо исполняют особое условие здания.
5. Ключевое условие состава — требование к бригаде для закрытой услуги. Оно проверяет прошлое или логичную комбинацию черты с характеристиками, а не отдельную профессию:

| Код | Условие считается выполненным |
|---|---|
| `СТРОИТЕЛЬСТВО` | строительное прошлое либо черта `Builder` |
| `ГРАМОТА` | писарское/учительское прошлое либо `Грамотный` при РАЗ 3+ |
| `ТЕХНИКА` | инженерное/механическое прошлое либо `Мастеровой` при РАЗ 4+ |
| `ТОРГОВЛЯ` | торговое прошлое либо `Бережливый` при ЭМП 4+ |
| `МЕДИЦИНА` | медицинское прошлое либо `Грамотный` при РАЗ 4+ и ЭМП 4+ |
| `КУЛЬТ` | жреческое прошлое либо `Верующий` при ЭМП 4+ |
| `ОХРАНА` | военное/охранное прошлое либо `Храбрец` при СИЛ 3+ и РАЗ 3+ |
| `МОРЕ` | морское прошлое либо ЛОВ 4+ и РАЗ 4+ |
| `ЧУДОТВОРЕЦ` | только черта `Чудотворец`; прошлое и высокий РАЗ её не заменяют |

Ключевое условие относится к функции, а не ко всем местам: например, больнице нужен хотя бы один медицинский специалист, но санитары и носильщики могут иметь другое прошлое. Скрипторий может быть укомплектован переписчиками, но его мистический эффект активируется только при назначенном `Чудотворце`.

### Полный порядок влияния жителя на работу

Расчёт должен быть видимым и идти в одном порядке:

1. **Доступность.** Учитывается живой и не выведенный из строя житель, которому назначены реальные QD. Взрослый даёт не более 2 QD в день, трудоспособный ребёнок старшего возраста — не более 1 QD; переработка добавляет реальный оплачиваемый QD, а не процент эффективности.
2. **Оплата.** Неоплаченный QD не создаёт результат. Явно отмеченный флаг добровольного труда является отдельным видимым исключением; пояснение к нему необязательно. Повышенная ставка улучшает довольство или удержание специалиста, но не покупает скрытый производственный множитель.
3. **Допуск.** Проверяются необходимые характеристики конкретного места. GM-переопределение допуска возможно только как явное подтверждение и не создаёт бонуса.
4. **Состав.** Для закрытой функции проверяется требуемое число профильных работников. Провал отключает именно эту функцию, а не всё здание и не вспомогательные места.
5. **Личная квалификация.** Для производственного QD складываются базовые `100%`, лучший бонус типажа, один бонус прошлого, максимум одна положительная и одна отрицательная рабочая черта.
6. **Общие условия.** После квалификации умножаются голод, исправность/обслуживание здания и явные временные эффекты событий. Они не меняют типаж и не создают новый QD.
7. **Выпуск.** Полученные целочисленные единицы работы двигают только обеспеченную сырьём линию; готовая продукция появляется целыми партиями.

Не являются самостоятельными бонусами производственной эффективности здания: подпись `role`, сама величина зарплаты, Репутация, Контроль, довольство поселения, число подходящих слов в прошлом, несколько одинаково полезных черт и черта `Лидер`. У `Лидера` есть отдельное правило руководства стройбригадой ниже. Недовольство должно проявляться через события, отказ от переработки, прогулы или уход, а не через постоянный скрытый процент: иначе поселение получает трудно читаемую двойную кару одновременно по событиям и производству.

Класс квалифицированного штата показывает, сколько профильных работников заложено в баланс при минимальном штате. В производстве профиль означает бонус типажа `+25%` или `+50%`; в остальных зданиях — прохождение допуска и ключевого условия:

| Класс | Расчётное число квалифицированных работников |
|---|---|
| A — обычный труд | `max(1, ceil(workersMin / 4))` |
| B — ремесло или служба | `max(1, ceil(workersMin / 3))` |
| C — сложная или критическая работа | `max(1, ceil(workersMin / 2))` |

Для здания с `workersMin = 0`, но доступными рабочими местами, расчётный профиль начинается с одного квалифицированного работника при фактическом использовании функции. Класс — ориентир экономики и подсказок, не дополнительный скрытый блокиратор. Порог характеристик можно сделать жёстким допуском сразу; незаполненное ключевое условие отключает только соответствующую закрытую функцию, но не снимает работников и не уничтожает здание.

Проверка доступности на текущем генераторе не выявила дефицита типов. В детерминированной выборке по 50 000 взрослых на каждый режим прибытия у обычных поселенцев около 60% имели одну характеристику 5+, 4,6% — две или больше, а 26,4% подходили под `РР*`. У целевых работников и специалистов одна выдающаяся характеристика встречалась примерно у 75%, две или больше — у 12,6–12,9%. Поэтому `+25%` является доступной специализацией, `+50%` остаётся заметно более редкой наградой, а баланс классов A/B/C не предполагает штат, целиком состоящий из двойных типажей.

## 4. Целочисленная эффективность и производство

Эффективность должна влиять на **накопление производственной работы**, а не дробить готовую продукцию и не создавать дробные QD.

- Один реальный рабочий QD всегда остаётся одним QD занятости и оплачивается как один QD.
- Базовый работник даёт `10 000` целочисленных единиц производственной работы за QD.
- Подходящий тип `+25%` даёт `12 500`, оптимальный `+50%` — `15 000`.
- Подходящее прошлое добавляет `1 000` единиц (`+10%`) один раз, независимо от числа совпавших слов или профилей.
- Одна подходящая положительная черта добавляет `1 000`, одна мешающая вычитает `1 000`; они могут взаимно погаситься. Несколько положительных или несколько отрицательных черт не складываются.
- Максимальный обычный профиль — `17 000`: оптимальный тип `+50%`, профильное прошлое `+10%` и положительная черта `+10%`. `Чудотворец`, `Builder`, `Лидер` и сюжетные черты не дают скрытого универсального прироста.
- Цена рецепта `N QD` равна `N × 10 000` единиц работы.
- Линия выпускает только целые завершённые партии. Неиспользованный целочисленный остаток остаётся прогрессом этой линии и переносится дальше.
- До начала партии линия резервирует полный целочисленный набор входных ресурсов. Остаток работы разрешено переносить только на уже обеспеченную ресурсами партию; без сырья лишняя часть QD остаётся простоем, а не «банком труда из воздуха».
- Голод, состояние здания и другие общие модификаторы применяются после сложения квалификации, в целых базисных пунктах. Например, профиль 125% при голоде 95% даёт `11 875` единиц, без float-арифметики.

Пример: рецепт стоит 3 QD, то есть 30 000 единиц. Обычный работник завершит партию за 3 QD. Работник `+25%` после 2 QD накопит 25 000, после третьего — завершит партию и, если сырьё следующей партии уже можно полностью зарезервировать, оставит в ней 7 500 прогресса. Без сырья излишек этого QD простаивает. Работник `+50%` завершит первую партию ровно за 2 QD. Выпуск и оплаченная занятость всегда целые.

В runtime бонус включён только у 41 уже экономически проверенного производственного шаблона: 32 здания с линейными рецептами, 5 с сезонными профилями и 4 с товарным животноводством. У сезонного хозяйства и животных бонус помогает закрыть требуемую работу, но не увеличивает биологический предел урожая, молока, шерсти или поголовья. Конюшня не считается производством, потому что её утверждённый профиль прямо не создаёт товарный выпуск.

### Отдельный руководитель стройбригады

Руководитель — отдельная оплачиваемая позиция и никогда не входит в `memberIds`, минимум из двух рабочих или их строительные кубы. Рабочий получает базовую ставку `12 ММ/день`, руководитель — `18 ММ/день`.

Должность доступна жителю с `Builder`; с чертой `Лидер` и РАЗ либо ЭМП 3+; с РАЗ 4+ и ЭМП 4+; либо со строительным прошлым и РАЗ либо ЭМП 4+. Наличие подходящего руководителя открывает строительный бросок. Черта `Лидер` дополнительно даёт ровно `+1к6` координации, но только при наличии двух рабочих. `Builder` вместо универсального куба сохраняет собственное правило месячного переброса. Один житель не может одновременно быть руководителем и рабочим той же или другой бригады.

У остальных зданий колонки `+25%/+50%` равны `—`. Типаж не умножает доход, цену торговли, Репутацию, довольство, развитие, Контроль, DR, медицинские койки, жильё, хранение или вместимость услуги. Воздушные корабли, исследования, обучение и иные проекты можно позднее подключить как отдельные обеспеченные ресурсами рабочие заказы, но не следует включать их неявно вместе с первой производственной миграцией.

## 6. Результат реализации

1. `workerPrimaryAttribute`, `primaryWorkerAttribute`, старые `suitableWorkerTypes` здания и `workerTypeEffects` удалены из исходного каталога и безопасно вычищаются из сохранённых экземпляров. Одноимённая настройка подходящих типов осталась только у самостоятельной механики строительной бригады.
2. Все 118 строк дерева и два сюжетных runtime-шаблона собраны в проверяемый манифест. Профили связываются по стабильному `templateId`; изменение сохранённых шаблонов и назначений проходит через явно разрешённый перенос. Исторический переход 61 шаблона/schema 70 не повторяется.
3. Schema 70 переносит `workerProfile`, утверждённые `workersMin/workersMax`, целочисленный прогресс и резерв партии. Существующий неподходящий работник не снимается: для него создаётся явный сохранённый GM-допуск.
4. UI показывает допуск, типовые бонусы, прошлое, положительные и отрицательные черты, условие состава и фактический производственный эквивалент отдельно от числа людей.
5. Жёсткий допуск проверяется и в интерфейсе, и на authority-GM пути как для обычного слота, так и для явного плана QD. Только GM может подтвердить сохраняемое исключение; оно даёт базовые `10 000` единиц без бонусов.
6. Производство, сельское хозяйство и товарное животноводство используют целочисленную работу. Сырьё резервируется полной партией, выпуск остаётся целым, а необеспеченный остаток не превращается в бесплатный банк труда.
7. Состав отключает только соответствующую закрытую функцию. Обычная работа Скриптория не требует дара; чудотворческий эффект требует живого, доступного, обеспеченного QD жителя с чертой `Чудотворец`. Явный QD считается назначением сам по себе и не требует невозможного дублирования жителя в legacy-слоте.
8. Поле профессии `skill` удалено из генерации, UI и сохраняемой модели. Миграция использует старое значение только один раз: известные устаревшие профессии отбрасывает, а неизвестное пользовательское значение сохраняет как черту.
9. Руководитель стройбригады хранится, назначается и оплачивается отдельно от рабочих. Без двух рабочих и подходящего руководителя строительный бросок не выполняется.

## 7. Утверждённые правила

- Типаж происходит только от характеристик 5+; точное название типажа не служит профессией или воротами допуска.
- Лучший бонус типажа равен `+25%` или `+50%`, профильное прошлое — `+10%`, максимум одна полезная и одна мешающая черта — `+10%/-10%`.
- Квалификация меняет только производственную работу, но не число QD, зарплату, доход, торговлю, Репутацию, довольство, развитие, Контроль, DR, медицину, жильё, хранение или вместимость.
- Жёсткими являются только перечисленные опасные или физически требовательные назначения; прочие пороги служат рекомендацией.
- Ключевой состав проверяет прошлое либо явно заданную комбинацию черты с характеристиками и отключает только зависимую функцию.
- Скрипторий ведёт обычное исследование без Чудотворца; редкий эффект требует назначенного Чудотворца. Черта генерируется независимо с шансом ровно `0,1%` и чаще выдаётся сюжетно.
