# Перевозки v2: независимая перепроверка и исправления

Проверено исходное состояние PR #13 `8f1a225b8217b2240a917546f78a22d31503f811` относительно `1d7dd80defe192ad4a9ccf1acde84a23fa4c5cac`. Все восемь находок первоначального аудита воспроизведены на рабочих функциях. Для поиска путей дополнительно использован независимый полный перебор простых путей на 12 небольших графах при шести бюджетах УРС; результат сравнивается с планировщиком, а не повторяет его алгоритм.

## Подтверждённые проблемы

| Находка | Причина и исправление | Проверка |
| --- | --- | --- |
| F1. Свой корабль недоступен для местной перевозки | Поселение и рынок в одном регионе сливались в одну точку. Теперь это разные остановки с принятой местной дистанцией 20 км, обработкой, подходом, пустыми челноками и выбранным возвратом. Стоянка в местном порту не завершает выход домой. | GM/player, покупка/продажа, две ходки, стоянка/возврат, повтор команды и фактические расходы. |
| F2. Пропущен допустимый обход | Проверка УРС выполнялась после выбора кратчайшего пути. Поиск теперь сохраняет альтернативы по длине и УРС, включая пустые перегоны; свой участок оставляет УРС для последующих участков. | Обход через точку без порта, независимый перебор 72 случаев, смешанная цепочка в обоих направлениях. |
| F3. Пропущена свободная дорога | Предварительный поиск удалял физические альтернативы по статической цене до проверки занятого расписания. Для v2 разные пути и последовательности перевозчиков сохраняются до планирования отправлений. | Две равные дороги: свободная сохраняет исходные срок и цену; явно выбранная занятая дорога сохраняет своё расписание. |
| F4. Собственное судно игнорирует среду риска | Базовый риск применяется с коэффициентами локаций и сезона. Наёмный коэффициент компании не переносится на собственный корабль. Для составного участка принят максимальный риск входящих связей, согласованно с наёмной услугой. | База 300 bps и среда ×4 дают 1200 bps; сезон ×2 также учитывается. |
| F5. Разные пределы чартерного парка | Настройка принимала 10000 машин, планировщик — только 1000. Общий предел 10000 используют настройка, форма и планировщик. | 1, 1001 и 10000 принимаются; 10001 отклоняется. |
| F6. Невесомый груз ждёт свободной вместимости | Полностью занятое отправление теперь допускает нулевую нагрузку. Положительная неделимая единица продолжает ждать достаточной вместимости. | Смешанная партия при полностью занятом регулярном рейсе. |
| F7. Удаление завершившего заказ поселения оставляет вечную бронь | Перед разрешённым удалением убираются только известные завершённые доли этого владельца. Общий рейс сохраняется для отстающего заказа и удаляется после всех обязательств; неизвестные ссылки остаются под защитой восстановления. | Удаление одного владельца, продолжение другого, очистка, неизвестная ссылка и запрет удаления незавершённых обязательств. |
| F8. Финансы корабля читают только старые продажи | Добавлено представление принятых v2-заказов по выходу корабля. Оно объединяет свои и наёмные расходы, пошлины, страхование и фактические поступления без повторного учёта бортовых проводок. Покупаемый товар остаётся запасом, а не эксплуатационным расходом. | Реальные GM/player-заказы, равенство с казной, частичная утрата и страхование, несколько заказов за выход, граница следующего выхода, скрытый рынок и отсутствие записей при просмотре. |

При расширении F2 найден дополнительный пробел: список наёмных услуг строился только из полностью наёмных путей. Теперь выбранный корабль может соединить поселение с доступным портом пересадки даже при отсутствии сквозного наёмного сообщения. Сохраняются прежние идентификаторы существующих услуг и ограничения поиска.

Финансовый результат включает целиком связанные перевозки. Если корабль уже дома, а наёмная часть ещё в пути, сравнение окончательного результата со сметой ждёт завершения доставки и расчётов. Ожидаемая выручка исключает уже известную утрату и порчу. Карточка заказа показывает отдельно потерянное, испорченное и страховую выплату.

## Целостность проверок

`check:all` раньше останавливался на вложенной команде `npm run transport:check`. Сборщик теперь раскрывает вложенные команды с проверкой отсутствующих скриптов и циклов и сохраняет однократное выполнение одинаковых Node-команд.

Два прежних ожидания изменены вместе с поведением. Проверка удаления владения теперь требует сохранности другого заказа и его физического расписания при удалении завершённой доли. Проверка маршрутной сети перенесена с удалённой v1-панели рынка на рабочий переход рынок → перевозки и выбор физической дороги в v2. Остальные утверждения сохранены; проверки не пропускались.

Новые постоянные сценарии: `transport-v2-routing-regression-check.mjs` и `transport-v2-finance-check.mjs`; общий тестовый адаптер вызывает настоящий authority executor и цикл исполнения. Всего в `transport:v2:check` 15 файлов. Формат хранения, производственные зависимости и правила записи данных мира не изменены.

Итоговая проверка 2026-11-01: `npm run check:all` — lint и 157 различных команд без ошибок, включая общие suites, Foundry 13/14, lazy boundaries и все 15 файлов v2. `npm run css:check` и `npm run perf:budget` также пройдены. Все восемь исходных независимых примеров после исправлений проходят. Дополнительно отдельно исполнены восемь местных сценариев обычного поселения (GM/player × покупка/продажа × стоянка/возврат); постоянный набор покрывает плавающее поселение. Итоговый diff проверен.

## Границы вывода

Одна цепочка на заказ, сбор всего груза перед следующей перевалкой, один собственный корабль, конечный поиск и фиксация сезонных условий при расчёте остаются ограничениями модели. Эти правила не обещают глобально оптимальную доставку или прогноз смены сезонов. Экономическое преимущество собственного корабля не гарантируется: оно зависит от профиля, экипажа, загрузки, начальной позиции и возврата. Тарифы и баланс не менялись ради получения такого преимущества.

Проверка выполнена вне работающего Foundry; данные мира и установленный модуль не изменялись. Статические проверки не заменяют проверку окон, фокуса, hooks и двух подключённых клиентов. Ручные сценарии перечислены в [инструкции проверки](transport-v2-validation.md).
