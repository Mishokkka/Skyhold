# Внедрение двух способов назначения на работу

Дата: 20 октября 2026 года. Основа: [согласованные правила и проверка реализации](hybrid-labor-implementation-review-2026-10-20.md).

Формат хранения ниже явно согласован пользователем 20 октября: «Да, согласую этот формат хранения». Реализация выполняется в ветке `feat/hybrid-labor-planning`; применение перехода к миру не выполняется.

## Что меняется для пользователя

У здания ГМ выбирает один способ работы:

- **Постоянный штат.** Человек занят в этом здании весь десятник. У него одна основная и, по желанию, одна резервная работа. При ожидании или выполненной цели он может выполнять резервную; когда основная снова требует труда, возвращается. Зарплата считается по одной согласованной ставке, включая вынужденный простой.
- **Задания по QD.** Жителю можно выделить часть времени здесь, а остальное — в другом здании. Число разных исполнителей за десятник не ограничивается числом прежних мест. При необходимости ГМ задаёт предел суммарного труда здания за десятник; вместимость партий и оборудования сохраняется отдельно.
- **Без работников.** Для пассивных объектов, в том числе обычного колодца. Отдельное техническое обслуживание сохраняется, если предусмотрено устройством объекта.

План повторяется при следующем проведении десятника. Игрок проводит только один десятник за раз. Внутренние четверти дня используются расчётом; сменить назначения в середине уже проводимого десятника нельзя. Строительство остаётся отдельной попыткой за весь десятник, стройбригада не переходит в другие здания.

У производственной линии можно указать общий объём подготовки в ЕД. Это одна цель всех её работников. Для товара с выдержкой подготовка не означает немедленную готовность. Начатая оплаченная партия не обрезается при уменьшении цели. Для случайного выхода точное количество не обещается.

## Какие сведения требуется сохранять

1. У здания — выбранный способ работы и отдельный предел QD, если он нужен.
2. У постоянного сотрудника — здание, основную и резервную работу, согласованную дневную ставку и разрешённые сверхурочные. Бесплатная работа требует отдельной договорённости ГМа.
3. В общем плане — заданное количество подготовки для каждой линии. Нынешние цели QD и закрепления сохраняются.

Старые здания и назначения не преобразуются при обычной загрузке. Для перехода будет предварительный просмотр: неоднозначные назначения, изменённые рецепты, превышение лимитов и недоступные линии должны быть показаны явно. Применение перехода к миру не входит в текущую разработку и проверку.

## Точный договор данных

Дополнительные поля необязательны; отсутствие означает прежнюю механику.

```js
building.labor = {
  version: 1,
  mode: "staff", // "staff", "qd" или "passive"
  capacityQd: null // null — отдельного предела нет; иначе целое >= 0
};
```

`workersMax` остаётся числом мест постоянного штата. Для QD не ограничивает число разных исполнителей. Предел `capacityQd` включает обычный и сверхурочный личный труд производственных и служебных задач, а не эффективный выпуск; его нельзя автоматически пересчитывать из личной нормы. Отдельная техническая проверка не занимает производственную мощность здания. Внешний технический специалист может обслужить и штатное здание, не становясь его постоянным сотрудником.

```js
person.staffAppointment = {
  version: 1,
  buildingId: "building-id",
  primaryFunctionId: "production:line-id",
  reserveFunctionId: "",
  wageDailyCopper: 12,
  overtimeQd: 0,
  volunteer: false,
  volunteerReason: ""
};
```

Обычное время берётся из текущей нормы жителя. Норма 0 не увольняет штатного сотрудника и не делает его доступным внешним заданиям. Другие гражданские назначения несовместимы с таким договором. Существующие поля места работы и штатных мест поддерживаются согласованно с договором; они не создают вторую зарплату.

```js
holding.workforcePlan = {
  version: 2,
  goals: [], // существующие цели труда
  locks: [], // существующие закрепления
  productionGoals: [
    { sourceId: "building-id", functionId: "production:line-id", preparedUnits: 20 }
  ]
};
```

План первой версии остаётся читаемым. Новая версия появляется при явном сохранении новых сведений. Общий план передаётся через действующий путь игрок → ГМ, с проверкой прав, версии состояния и повторов запроса.

## Порядок работы и проверки

1. Исправить доказанные двойной расход труда и безрезультатное частичное списание при сборе.
2. Добавить данные и общие проверки несовместимых назначений во всех редакторах.
3. Подключить штат, единую ставку, выбор основной/резервной и общую цель производства.
4. Проверить ежедневный уход, периодные полевые работы, обслуживание и профильные услуги.
5. Адаптировать существующее компактное окно; изучить каждый стандартный шаблон и подготовить переход с просмотром конфликтов.
6. Проверить расчёты и сохранение вне Foundry, включая права игрока и повтор проведения соседних десятников. Подготовить короткую ручную проверку ГМа/игрока.
7. После завершения создать PR и запросить CodeRabbit review. Замечания проверить и исправить до отчёта о готовности.

Проверки Node не заменяют проверку окон и действий в живом Foundry. Новые смены, расписание выходных и отмена незавершённого труда не входят в эту работу.
