# Итоговая сверка трёх аудитов — 28 сентября 2026

Проверены `D:/audits/TechAudit1.md`, `D:/audits/TechAudit2.md` и `D:/audits/applied-fixes-2026-09-23.md` против текущих исходников. Содержимое документов рассматривалось как утверждения для проверки, а не как разрешение менять мир. Цель проверки — Foundry VTT 13.351 / Forbidden Lands 13.0.5 с сохранением существующей совместимости с Foundry 14.

## Вердикт

Аудиты полезны, но смешивают разные состояния проекта, реальные дефекты, устаревшие тесты и предложения по развитию продукта. Применять все рекомендации буквально было бы небезопасно. В частности, заново менять систему полномочий GM, скрывать общий план обороны, менять баланс или автоматически повторять миграцию не требуется.

Подтверждены и исправлены потери ссылок на новый каталог в пределах одной записи, небезопасное удаление используемых записей, повторное применение завершённых событий, повторные клики покупки/импорта, отсутствие постоянной квитанции обычного player patch, ошибки закрытия/сохранения окон, повторная загрузка CSS и ряд конкретных проблем доступности. Исправлены проверки, которые сравнивали исторический проект v14 с действующим каталогом v16 либо не учитывали уже реализованные архитектурные изменения.

Утверждение ST-01 о двух независимых обычных GM-коммитах не описывает нынешний путь записи: уже существует единый authority-GM и проверка ревизии. Это кооперативный клиентский протокол, а не серверная транзакция с CAS. Отдельный остаточный риск — авария между изменением Actor и world settings; компенсация существует, её отказ теперь явно сообщается. Обещать атомарность двух систем было бы неверно.

World settings доступны клиентам. Фильтры GM-полей управляют интерфейсом, но не обеспечивают секретное хранение. Это уже описано в README. Для настоящей конфиденциальности нужен отдельный согласованный проект хранения; здесь формат данных не менялся.

## Почему изменены проверки

Ни одна ошибка механики не исправлялась ослаблением assertions. Устаревшие структурные ожидания заменены точными контрактами нынешней архитектуры:

- временные каталоги исключены из обхода; рабочие `scripts`, `templates`, `styles`, `docs` проверяются;
- вычислительные модули могут импортировать только явно перечисленные чистые politics/presence helpers; запрет Foundry/DOM и скрытых динамических зависимостей сохранён, чистота helpers проверяется отдельно;
- рынок проверяется в выделенной вкладке, общие действия корабля — вместе с отдельным ship window и динамической кнопкой отправления;
- CSS-контракт цены использует существующий семантический typography token;
- reset harness задаёт текущую ревизию и дополнительно проверяет её передачу; реальный reset не запускался;
- v14 proposal не сравнивается с v16. Для годовой модели точный текущий маршрут содержит 24 здания, storage 1600; старые 26 зданий с elevator давали другую стоимость. Новые baseline cash: −71532 / −57636 / −74292. Проверки сохранения еды, труда, вместимости, расходов и отсутствия бесплатных поступлений сохранены.

2. GM: новый custom resource и его рецепт/стоимость/топливо в одной записи; скрытие ресурса; попытки коллизии ID, удаления используемого ресурса и replace-import с зависимостями. Отказ должен сохранять исходные данные целиком. Допустимый preview не является разрешением Apply.
3. Покупка: двойной клик, отмена confirmation, ошибка записи, закрытие во время операции. Проверить одну оплату и отсутствие самопроизвольного открытия окна.
4. Редакторы: изменить поле и сразу закрыть; отключить соединение во время сохранения; повторить успешное сохранение. Проверить сохранение текста, курсора и отсутствие повторных listeners. Для импорта — смена preview во время чтения файла, двойной Apply, close во время успешной/неудачной записи.
5. Склад: только клавиатурой открыть «…», выбрать действие стрелками, закрыть Escape, проверить возврат фокуса; перенос нескольких строк; ввод количества выше max. Player с правом склада может только разрешённые операции; добавление ресурса вручную остаётся GM-only.
6. Отряд/бригада/переселение/очистка логов/связь графа: отмена не меняет данные; подтверждение делает ровно заявленное действие. Для событий повтор applied/done не меняет казну/ресурсы.
7. Окна рынка, корабля, mass-combat: отказ загрузки шаблона/стилей и повторное открытие; stylesheet после сетевой ошибки загружается заново. Основное окно быстро открыть/закрыть: overlay не возвращается.
8. GM/player: окно десятника не показывает игроку gmText; общий план обороны остаётся общим. Screen reader объявляет колонки рынка, фильтры, кнопки и checkbox.
9. Foundry 13.351/FBL 13.0.5 и доступная Foundry 14: 1366×768 и узкое окно около 840px, масштаб 125–150%, длинные имена, горизонтальная прокрутка жителей, sticky headers, край меню шаблона, tooltip над диалогом, disabled/focus states. Статические CSS-тесты этого не заменяют.
