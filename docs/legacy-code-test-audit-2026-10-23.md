# Аудит неиспользуемого кода и тестов

Дата: 23 октября 2026 года. Исходный head PR № 4: `136ad3e308c0abf6d4f10a2365c6b330385f2ea8`.

## Метод и границы доказательств

Проверены точки входа `module.json`/`main.js`, импорты и динамические загрузки, композиция доменов, реестры действий, прямые вызовы, шаблоны, тесты и контракты совместимости. Статический граф использовался для поиска кандидатов, затем каждый удаляемый метод проверялся отдельно. Отсутствие исполнения в тестах само по себе не считалось доказательством ненужности.

В аудите участвовали три независимых направления: экономика и старые правила труда; планировщик, миграции и интерфейс; достижимость и качество запуска тестов. Удаления из доменов жителей и подключение тестов дополнительно проверены другим участником аудита.

Граф от основного runtime-входа достигает 397 из 406 JavaScript-модулей. Девять остальных не удалены: четыре исходных каталога нужны генераторам, остальные являются фасадами импорта, включая поддерживаемый публичный `scripts/data.js`. Макросы и внешние потребители не обязаны присутствовать во внутреннем графе.

Из 191 исходного dev-модуля 185 достижимы через npm-команды и импорты их проверок. Шесть остальных — генераторы `build-*`. Неиспользуемого тестового файла не доказано; тестовые файлы не удалялись. Сохранён и независимый запуск проверки пищевых партий из economy/storage suites: обеим группам нужно собственное покрытие.

## Удалённые остатки

Для всех 14 методов проверка runtime, dev, шаблонов и документации не выявила действующих вызовов вне удаляемых цепочек. Историческое упоминание affordability-helper в proposal не является runtime-вызовом. Регистрация действий не формирует имена удалённых методов динамически. Явных контрактов совместимости для этих приватных методов нет.

## Исправленный пробел в запуске тестов

Общий `npm run check` не запускал действующие проверки распределения QD, настраиваемого бюджета труда, сохранения и прав планировщика, а также его окна. Они были доступны отдельными командами, поэтому считать их устаревшими было бы ошибкой.

Добавлена `scripts/dev/suites/workforce.mjs`, которую общий check ожидает после hybrid-suite. Существующие `labor-budget-check.mjs`, `workforce-planner-check.mjs`, `workforce-planner-window-check.mjs` получили вызываемые функции и guards самостоятельного запуска. Их импорт больше не исполняет тесты; прежние npm-команды сохранены. Восстановление подменённых globals проверено двумя последовательными запусками новой suite в одном процессе.

AST-сравнение с исходными файлами подтвердило неизменность всех 367 assertion-вызовов в изменённых dev-файлах, включая 199 в трёх обёрнутых проверках. Assertions не удалялись, не пропускались и не ослаблялись.

## Сохранённые старые пути

- `buildingLaborMode` возвращает `legacy`, если `labor` отсутствует. Нормализация сохраняет это состояние; переход требует отдельного явного действия. Старые расчёты и их тесты продолжают защищать немигрированные и смешанные поселения.
- Планировщик, `workAssignment`, `assignedWorkerIds`, миграционные `lineMappings`, GM/player authority, revision/replay и rollback-контракты остаются используемыми возможностями.
- Шесть `_summarize…` адаптеров сохранены: для них есть явный контракт совместимости в `repository-contracts.mjs`, хотя внутри runtime итоговый отчёт использует общий summarizer.
- Публичные фасады и исходные каталоги генераторов сохранены. Удаление таких точек входа требует отдельного доказательства отсутствия поддерживаемых потребителей.

## Оставшаяся ручная проверка

Live Foundry не запускался, миграции и данные мира не изменялись. Статические и изолированные Node-проверки не заменяют ручной smoke в Foundry 13.351 / Forbidden Lands 13.0.5 и на поддерживаемом Foundry 14:

1. ГМ: открыть смешанное поселение со старыми и новыми режимами, планировщик, изменить и сохранить распределение; проверить прогноз десятника.
2. Игрок: открыть доступный планировщик, сохранить разрешённое изменение через authority-GM и проверить отказ для недоступного изменения.
3. ГМ: открыть редактор жителя через контекстное меню и проверить отображение фильтров, строительной бригады и жалованья военных.

Кодовых или статических блокеров после проверок нет. Общий check покрывает подключённые группы; он по-прежнему не является обещанием запуска каждой отдельной доменной команды из package.json.
