# Окно десятника: контракт

Статус: действующее окно Preview/Apply и сохранённого результата. Один десятник — 40 QD; пакет считает полный цикл последовательных периодов на черновиках и записывает единый атомарный итог. Календарь проверяется повторно перед Apply и использованием кэша окна. При первой привязке без сохранённой даты период заканчивается текущей датой Calendaria, начало определяется до производства.

Неразобранные эффекты предыдущего события нужно применить или перенести в план; отложенные события сами время не блокируют. Для перевозок v2 есть отдельный [разбор физических исходов до хозяйственного Preview](transport-tenday-time.md); решение сохраняется явной командой, не проводя чужое хозяйство. Клиентский рейс судна использует собственные решения капитана.

## Продуктовый контракт окна

### Состояния

1. **Расчёт** — окно видно сразу, world state не меняется.
2. **Предпросмотр** — подготовленный snapshot зафиксирован; доступны четыре представления и кнопка «Провести десятник».
3. **Устарел** — владение или влияющий каталог изменился; применение заблокировано, доступен пересчёт.
4. **Применение** — повторный клик заблокирован.
5. **Итог** — то же окно показывает фактически записанный snapshot и operation id.
6. **Ошибка** — причина видна в окне без ложного утверждения о состоянии commit.

### Представления

- **Сводка** — номер/диапазон QD, дата, казна, пища, стройки, события и только значимые предупреждения.
- **Хозяйство** — производство, расходы, питание, доход, торговля, стройки/ремонт и поставки; пустые секции скрыты.
- **События** — до commit показывает план проверок и подошедшие запланированные события; после commit раскрывает выпавшие события, репутационные броски и ожидающие эффекты.
- **Точный diff** — компактные строки `до → после` для казны, ресурсов по комнатам, предметов, зданий, жителей, развития, модификаторов, поставок и часов владения.

### Правила информации

- Не повторять одну и ту же величину в нескольких секциях без новой причины.
- Не показывать «Нет изменений» для каждой пустой категории; достаточно одного спокойного состояния сводки.
- Формулы и сырые броски находятся в деталях, а не в главной сводке.
- Голод, дефицит казны, пропущенные операции, stale preview и подошедшие события всегда видимы.
- Случайные результаты фиксируются вместе с подготовленным snapshot, но до commit окно показывает только план проверок. Это не раскрывает событие для бесплатного переброса.
- Применяется конкретное `holdingId`, с которым окно было открыто; текущая вкладка большого менеджера не является authority.
- Chat message короткий и best-effort: ошибка чата не отменяет и не маскирует успешный commit.

## Архитектурная граница

- `scripts/engines/tenday/*` — чистое сравнение snapshot и структурированная сводка; без Foundry/DOM.
- `scripts/apps/tenday-app.js` — ApplicationV2 state machine, вкладки, focus и действия пользователя.
- `scripts/apps/domains/events/economy-events.js` — prepare/apply orchestration и интеграционные side effects.
- `scripts/apps/domains/events/gm-events.js` — подготовка/фиксация результатов таблиц событий без второй world transaction.
- `templates/tenday-app.hbs` — только представление готового context.
- `styles/parts/tenday/tenday-window.css` — единственный CSS-owner окна.

Подготовленная операция содержит `operationId`, `holdingId`, QD, dependency hash, исходный и итоговый snapshot, структурированный economy report, event result и change set. Расширения должны добавлять собственный блок результата, не разбирать HTML и не дописывать произвольный текст в общий массив.



## Подключённые системы и границы

Политика, обслуживание, корабли и перевозки подключены. Полный цикл каждого десятника пакета считается последовательно на изолированных данных, Apply записывает один результат. Политические итоги и ранние события сохраняются по периодам; более 40 событий отклоняются до записи.

До хозяйственного Preview влияющие перевозки v2 проходят [разбор на физических датах](transport-tenday-time.md). Запись решения — отдельная явная GM-операция, не проведение чужого хозяйства. Клиентские договоры корабля сохраняют [собственное время и отдельный итог](ships-world-stage.md); предполагаемая плата не становится доступной казной до подтверждённого результата.

Сравнения периодов, регулярные приезжие и extension API событий — [проекты](mechanics-expansion-roadmap.md). Проверки: `tenday:check`, `events:check`, `suite:storage`; [ручная матрица](manual-foundry-smoke-matrix.md).
