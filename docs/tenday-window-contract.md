# Окно десятника: контракт

Актуализировано 2026-09-06. Документ сохраняет контракт реализованного операционного цикла. Историческое описание прежнего диалога и выполненный план работ удалены. Статические проверки не заменяют [ручную проверку Foundry](manual-foundry-smoke-matrix.md).

**Сверка 03.10.2026.** Окно и подготовка/применение периода **готовы в коде**; Extension API и сравнение периодов — **проект**. [Объективное ревью и основания статусов](proposals-review-2026-10-03.md): оценены также связанные технические задачи.

## Продуктовый контракт окна

### Состояния

1. **Расчёт** — окно видно сразу, world state не меняется.
2. **Предпросмотр** — подготовленный snapshot зафиксирован; доступны четыре представления и кнопка «Провести десятник».
3. **Устарел** — владение или влияющий каталог изменился; применение заблокировано, доступен пересчёт.
4. **Применение** — повторный клик заблокирован.
5. **Итог** — то же окно показывает фактически записанный snapshot и operation id.
6. **Ошибка** — причина видна в окне без ложного утверждения о состоянии commit.

### Представления

- **Сводка** — номер/диапазон QD, дата, казна, пища, стройки, события и только значимые предупреждения.
- **Хозяйство** — производство, расходы, питание, доход, торговля, стройки/ремонт и поставки; пустые секции скрыты.
- **События** — до commit показывает план проверок и подошедшие запланированные события; после commit раскрывает выпавшие события, репутационные броски и ожидающие эффекты.
- **Точный diff** — компактные строки `до → после` для казны, ресурсов по комнатам, предметов, зданий, жителей, развития, модификаторов, поставок и часов владения.

### Правила информации

- Не повторять одну и ту же величину в нескольких секциях без новой причины.
- Не показывать «Нет изменений» для каждой пустой категории; достаточно одного спокойного состояния сводки.
- Формулы и сырые броски находятся в деталях, а не в главной сводке.
- Голод, дефицит казны, пропущенные операции, stale preview и подошедшие события всегда видимы.
- Случайные результаты фиксируются вместе с подготовленным snapshot, но до commit окно показывает только план проверок. Это не раскрывает событие для бесплатного переброса.
- Применяется конкретное `holdingId`, с которым окно было открыто; текущая вкладка большого менеджера не является authority.
- Chat message короткий и best-effort: ошибка чата не отменяет и не маскирует успешный commit.

## Архитектурная граница

- `scripts/engines/tenday/*` — чистое сравнение snapshot и структурированная сводка; без Foundry/DOM.
- `scripts/apps/tenday-app.js` — ApplicationV2 state machine, вкладки, focus и действия пользователя.
- `scripts/apps/domains/events/economy-events.js` — prepare/apply orchestration и интеграционные side effects.
- `scripts/apps/domains/events/gm-events.js` — подготовка/фиксация результатов таблиц событий без второй world transaction.
- `templates/tenday-app.hbs` — только представление готового context.
- `styles/parts/tenday/tenday-window.css` — единственный CSS-owner окна.

Подготовленная операция содержит `operationId`, `holdingId`, QD, dependency hash, исходный и итоговый snapshot, структурированный economy report, event result и change set. Расширения должны добавлять собственный блок результата, не разбирать HTML и не дописывать произвольный текст в общий массив.


## Отложенные расширения и проверка

Корабли подключены к расчёту периода после рыночной логистики и до финансирования: возвратившийся бортовой остаток доступен общей казне в этом расчёте. Продвижение и завершение меняют только snapshot до Apply; плата, остаток, статус и история фиксируются вместе с остальным результатом. Change set и сохранённый payload содержат группу «Корабли». Возврат бюджета — внутренний перевод, чистый результат рейса учитывается отдельно. Это расчёт на границе периода, без посуточного распределения расходов поселения. Проверка повторного Apply, stale и финансового примера описана в [чеклисте кораблей](ships-manual-smoke.md).

Для случайного контракта десятник только доводит рейс до `awaitingOutcome`. Коммерческие кубики и происшествие не бросаются в preview и не входят в его скрытую копию. Отдельная защищённая команда подведения итога после Apply создаёт публичный исход и проводит его один раз; до этой команды предполагаемая плата недоступна поселению. Если назначена задержка, её время отсчитывается от решения и завершается последующим десятником без повторного броска. Любая такая команда делает прежний зависящий от владения preview устаревшим. Ручной фиксированный рейс сохраняет автоматическое завершение при расчёте периода.

Extension API для новых источников событий и полезные сравнения с прошлым периодом остаются дальнейшей работой. Ручные keyboard/focus, viewport 1360×900/1024×768, GM/игрок и V13/V14 проверяются пользователем после затрагивающей их реализации. Отказ чата не должен отменять успешный commit, stale и повтор Apply не создают частичной или второй операции.

Обслуживание и Политика подключены. При действующей или ранее начатой Политике/дани пакет выполняет полный штатный цикл каждого периода A…B на изолированных черновиках; Apply сохраняет один атомарный результат без повторных бросков. Оплаты, Влияние, сроки указов и события проверяются на каждом шаге. Сводный отчёт хранит политические итоги по периодам; ранние события остаются доступными после тихого последнего периода. Пакет с более чем 40 событиями отклоняется до записи, чтобы не терять решения. Актуальные исправления, ограничения старых данных и ручной GM/player smoke перечислены в [плане Политики](politics-remediation-plan.md). [Регулярные приезжие](newcomer-arrival-proposal.md) ещё не реализованы. Исторический [план переноса](building-preparation-revision-2026-09-05.md) не определяет текущую готовность этих функций.

Целевые проверки: `npm run tenday:check`, `npm run events:check`, `npm run suite:storage`; при изменении представления — `npm run ui:check` и `npm run css:check`.
