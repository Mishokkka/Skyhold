# Внешний рынок: компактная продажа со склада

Форма продажи раньше постоянно занимала нижнюю часть рынка, включая пустой склад. Теперь она появляется только при положительном количестве ресурсов с отметкой «к продаже» и изначально свёрнута. Текущие продажи и архив имеют отдельные сворачиваемые секции и доступны после ухода последнего товара со склада.

Раскрытие сохраняется при обновлениях в течение жизни окна; настройки мира для этого не записываются. Переход из окна корабля раскрывает форму или секцию нужной продажи. Подтверждение сделки остаётся действием GM.

## Выполненные проверки

- `npm run market:ui:check`: реальный контекст приложения для GM/игрока, пустой/неотмеченный/нулевой/зарезервированный запас, отсутствие спроса, лимит количества, кнопка «Макс.», отдельные заказы/архив, сохранение раскрытия и переход из корабля.
- `npm run market:check`, `npm run ui:check`, `npm run css:check`, `npm run compat:check`, `npm run lint`, `node scripts/dev/ship-management-ui-check.mjs`: успешно.
- Отдельный локальный макет с настоящими Handlebars-шаблоном и CSS в Edge: размеры 1260×760, 800×660 и 600×660; длинные названия и 12 строк; отсутствие горизонтального переполнения новых блоков; недоступные игроку элементы; сворачивание клавишей Space. Свёрнутая форма занимает 39 px в этом макете.

Макет не воспроизводит полный жизненный цикл Foundry, его тему и сетевое обновление. Живая проверка не выполнялась.

## Ручная проверка в Foundry

Цель: Foundry 13.351 / Forbidden Lands 13.0.5; повторить основные действия на Foundry 14. Выполняется пользователем в тестовом мире.

1. Без отмеченных ресурсов и истории продаж открыть рынок: нижнего блока нет. Отметить положительный запас «к продаже»: появляется одна свёрнутая строка «Продажа со склада». Нулевой запас сам по себе форму не показывает.
2. Раскрыть форму, изменить количество, страховку и рынок. Секция остаётся раскрытой, прокрутка списка сохраняется. Свернуть и обновить данные склада: она остаётся свёрнутой. Проверить Tab и Space/Enter на заголовках.
3. Выбрать несколько материалов, в том числе хранящихся в разных помещениях. «Макс.» ограничивается свободным запасом и спросом. Уже зарезервированный товар повторно не выбирается. Без спроса видна причина; без выбранного количества финансовые расчёты скрыты.
4. Сравнить наёмную доставку и свой корабль. Видны расходы сейчас, выручка после доставки, срок и остаток казны. Перевод на борт показан отдельно; подробности содержат налоги, перевозчика и покупателей.
5. Подтвердить тестовую продажу. Убедиться, что счётчик текущих продаж обновился, в раскрытой секции доступны прежние действия. После ухода последнего отмеченного товара форма исчезает, заказ остаётся доступным. После завершения доступен архив.
6. При дорожном событии GM видит «Нужно решение GM» в свёрнутом заголовке текущих продаж. Раскрыть секцию и проверить действия решения/отмены. Игрок видит доступные ему статусы без скрытого предложения исхода; оформление сделки недоступно даже при разрешённой работе со складом.
7. Из окна корабля открыть подготовку продажи и конкретный заказ: нужная секция раскрывается и получает фокус. Текущий выбор покупок и количества продажи сохраняется.
8. Уменьшить окно и проверить длинные названия, большой список товаров, оба типа доставки и подробности расходов. Прокруткой должны быть доступны все кнопки, а сворачивание должно возвращать место каталогу.
