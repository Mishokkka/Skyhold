# Исправление переноса производственных циклов

Исправлены две причины ложных препятствий при переходе каталога v16 → v17:

- Открытое окно миграции сохраняло старый расчёт после изменения или удаления построек. Теперь событие изменения данных вызывает новый расчёт без записи в мир, с сохранением прокрутки и фокуса.
- Проверка запрещала перенос любой начатой партии, даже при неизменных правилах производства. У стандартных Лесоповала и Каменоломни рецепты v16 и v17 совпадают. Теперь их корректные начатые партии переносятся вместе с прогрессом, зарезервированным выпуском, чеком сырья и накопленным дробным бонусом. Удалять здания для такого переноса не требуется.

Проверка по-прежнему блокирует несовместимый рецепт, отсутствующую линию и неполное состояние партии. Готовый выпуск не переносится в другой ресурс только из-за совпадения идентификатора линии. Препятствия теперь содержат название поселения: миграция проверяет все поселения мира, а не только открытую Лапуту.

Конкретное состояние пользовательского мира не исследовалось. Поэтому нельзя утверждать, что сообщение после удаления было исключительно старым расчётом: одноимённая постройка могла находиться в другом поселении.

## Изменённые файлы

- `scripts/workflows/buildings/catalog-migration.js` — проверка совместимости и сохранение состояния производства, принадлежность препятствий поселению.
- `scripts/workflows/buildings/catalog-conflicts.js` — чеки сырья и дробный бонус отнесены к состоянию производства.
- `scripts/apps/editors/building-catalog-migration.js` — обновление расчёта, очистка подписки при закрытии, запрет применения устаревшего подтверждения, сохранение текста ошибки.
- `templates/building-catalog-migration.hbs` — название поселения у препятствия и пояснение сохранения партий.
- `scripts/dev/building-catalog-*-check.mjs` — регрессии переноса, удаления, прав игрока и подтверждения. Устаревшее ожидание целевой версии 16 заменено проверкой актуальной версии каталога.

## Проверки вне Foundry

`npm run building:migration:check`, `npm run suite:data`, `npm run ui:check`, `npm run lint`, `npm run compat:check` и `npm run css:check` прошли. Diff проверен относительно сохранённых перед исправлением копий файлов: в рабочей папке нет репозитория Git.

Проверены: перенос и последующее завершение партии без повторной оплаты; сохранение готового выпуска и резервов после нормализации; блокировка изменённого рецепта; независимая проверка препятствий при Apply; повторное применение без записи; обновление открытого окна после удаления; указание другого поселения; отсутствие записей при просмотре; запрет Apply для игрока; отказ при изменении данных во время подтверждения; удаление подписки при закрытии окна.

## Что проверить вручную

Обновить страницу Foundry у ГМа и игроков, затем заново открыть «Миграцию каталога зданий». Для актуальных стандартных Лесоповала и Каменоломни начатый цикл сам по себе больше не должен блокировать обновление. Если препятствия остались, проверить указанное у них поселение. Дополнительное удаление построек не требуется.

На тестовой копии мира:

1. ГМ: оставить окно миграции открытым, изменить название постройки в менеджере. Расчёт должен обновиться, прокрутка и фокус не должны перескакивать.
2. ГМ: при открытом подтверждении миграции изменить данные со второго клиента. Подтверждение старого расчёта должно завершиться понятным отказом без записи.
3. Игрок: проверить, что действие миграции недоступно; просмотр и обновления окна не предоставляют право менять настройки мира.
4. ГМ: после явного применения на тестовой копии проверить сохранность жителей, казны и производственного прогресса; последующий выпуск партии не должен повторно списывать сырьё.

Живая проверка в Foundry и применение миграции в пользовательском мире не выполнялись. Уже удалённые пользователем здания этим исправлением не восстанавливаются.
