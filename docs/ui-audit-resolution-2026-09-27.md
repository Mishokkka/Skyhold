# Решения после двух UI-аудитов

Дата: 27 сентября 2026 года. Реализация разрешена пользователем после окончательной сверки UIAudit1/UIAudit2. Данные мира не изменялись; миграции и импорты не запускались. Карточки зданий остаются отложены.

## Исправления подтверждённых проблем

| Находка | Результат | Основные владельцы |
|---|---|---|
| OWN-01: пересекающиеся записи ГМов | GM-коммиты выполняет один выбранный активный ГМ через общую очередь с player-командами. Устаревшая ревизия отклоняется. Повтор transport-запроса использует тот же ID и сверяет содержимое; отправитель проверяется вне payload. `set()` сохраняет ревизию исходного снимка. | `scripts/data/gm-write-authority.js`, `store.js`, `split-storage.js` |
| OWN-02: потерянная цель владения | Выявленные обработчики больше не подставляют первое владение. ID фиксируется до ожидания очереди/ленивого открытия. Явно заданная отсутствующая цель content pack вызывает ошибку Preview. | `scripts/apps/domains/holding-domain.js`, `events/*`, `child-window-domain.js`, `scripts/data/content-packs.js` |
| OWN-03: строительные повторы | Результат связан с полным нормализованным запросом и пользователем, включая исходную ревизию. Несовпадающий повтор не пишет и не бросает кубики. Старые записи без полной подписи отклоняются безопасно. | `scripts/apps/construction-operation-executor.js` |
| OWN-04: ID | Добавление/переименование проверяет коллизии. Проверка на границе записи не допускает увеличения числа дублей владений, ресурсов, локаций, жителей и зданий. Существующие дубли не исправляются автоматически. | `scripts/data/entity-identity.js`, `holding-operations.js`, `collection-operations.js`, редакторы Resource/Region |
| OWN-05: устаревший черновик событий | Сохранение сверяет снимок именно таблиц событий. При внешней правке черновик остаётся в окне; чужая новая версия не перезаписывается. Изменение другой части владения не блокирует сохранение таблиц. | `scripts/apps/editors/random-event-editor.js` |
| OWN-07: устаревший callback FilePicker | Callback проверяет открытое окно, актуальность DOM-поля и ID ресурса. Независимые дочерние редакторы не закрываются принудительно. | `scripts/apps/editors/resource-catalog-editor.js` |
| OWN-08: изменяемый `view()` | Общий кэш заморожен рекурсивно. `get()` по-прежнему возвращает отдельный редактируемый черновик. | `scripts/data/split-storage.js` |
| OWN-09: Laputa rollback | Встроенная замена запрашивает снимок предыдущего согласованного состояния перед реальной записью. Сам импорт не запускался. | `scripts/data/store.js` |
| OWN-11: рендер после закрытия | Закрытие отменяет поколение очереди; поздний `requestRender()` не открывает окно. Явное повторное открытие разрешено, старая очередь не стирает новую. | `scripts/apps/common/render-scheduler.js` |
| UI-12: reduced motion | Системная настройка отключает вращение загрузчика и декоративные переходы склада/боя. При статичном загрузчике видна подпись «Загрузка…». | `skyhold-core.css`, `current/skyhold-current-storage.css`, `mass-combat-base.css`, `mass-combat-dialogs.css`, главный loading overlay |

Проверка authority выполняется перед каждым setting-write. Это защита клиентского исполнителя; серверного атомарного CAS в Foundry settings она не добавляет. Переключение authority во время уже отправленной записи требует ручной проверки. При timeout после возможной записи пользователь должен обновить данные перед повторным действием; запрос не пересылается автоматически новому ГМу с неоднозначным результатом.

Изменение карточек зданий не выполнялось. В `building-events.js` затронута только безопасность выбора целевого владения; внешний вид карточек и их CSS-владение сохранены.

## Новая пачка согласования

Открытие: **ГМ → Согласование интерфейса → Открыть сравнение**. Окно называется «После двух UI-аудитов». Существующая кнопка остаётся в обычной карточке dashboard, отдельно от верхней навигации.

Десять практических пар «Сейчас / Предлагается»: поля остальных редакторов, поиск, важность кнопок, заголовки секций, предупреждения/ошибки, основной текст/заголовки, радиусы/плотность, карточки выбора, клавиатура вкладок, узкое самостоятельное окно.

Стрелки/Home/End переключают только демонстрационные вкладки. Кнопка «Узкое окно» сужает оба образца: текущая сетка остаётся двухколоночной, предлагаемая перестраивается по собственной ширине. Выбор решения и комментарии меняют только локальный черновик и текст для копирования. Новые образцы не применяют CSS к рабочим окнам и не пишут settings. Прежние 6 решений по элементам и 8 решений по палитре/типографике сохранены в архиве окна.

Слева воспроизведены образцы существующих ролей из нескольких CSS-владельцев, справа предложены варианты. Это компактные образцы, а не снимки рабочих окон Foundry. Подпись 10 px, зазор 2 px, общие иконки 32 px с плотными исключениями и сохранение очень мелких подписей учитывают прежние решения пользователя.

Внешний вид и взаимодействие проверены в изолированном локальном предпросмотре с настоящими обработчиками окна согласования и CSS модуля. Предпросмотр использовал искусственные данные; Foundry не открывался. Проверены смена вкладки стрелкой/Home/End, roving tabindex/панели, ширина образцов 160 px и запись собственного варианта в сводку.

## Остальные позиции аудитов

Обязательные BaseApp, singleton всех редакторов, универсальные partials, лексический порядок классов, один размер checkbox и механическое округление всех размеров не вводились: окончательная сверка не подтвердила их как необходимые исправления. Установка глобальных hooks при hot reload, общая последняя позиция карты, фасад уведомлений и полная локализация остаются отдельными решениями по продукту/архитектуре. В обычном запуске соответствующие дефекты не доказаны либо требуют дополнительных требований. Существующие общие chips, empties, таблицы, palette и adapters не переписывались.

## Проверки

Прошли `suite:storage` (включая новый `ui-ownership-characterization-check.mjs`), `construction:check`, `events:check`, `content:check`, `suite:data`, `ui:check`, `css:check`, `lint`, `compat:check`, `lazy:check`, `perf:budget`. CSS: 0 `!important`, один владелец цветов, проверяемый контраст проходит. Совместимость проверена статически для Foundry 13/14; тяжёлые окна остаются ленивыми.

Проверка `suite:structure` имеет известный исходный блокер CRLF в несвязанных файлах; walker также захватывает старые материалы `.codex-tmp`. Он не устранён этой задачей. Полный релизный `check`/package не заявляется выполненным. Локальных Git-метаданных нет; изменения просмотрены через `git diff --no-index` относительно сохранённого начала задачи, новые файлы просмотрены отдельно.

## Ручная проверка в Foundry — остаётся пользователю

1. Перезагрузить клиентов, открыть менеджер от ГМа, перейти во вкладку ГМ: верхняя навигация полностью видна. Открыть сравнение, проверить прокрутку/ресайз, 10 новых пар и архив прежних решений. Выбор и копирование не меняют мир.
2. С двух активных GM одновременно изменить разные поля одного владения: один устаревший черновик получает конфликт; первая правка сохраняется. Проверить GM-action на вторичном ГМе, player-action через authority и запрет player на GM-коммит. Затем повторить со сменой активного authority/потерей ответа.
3. Открыть два редактора таблиц событий одного владения, сохранить первую правку, затем вторую: вторая предупреждает о конфликте и сохраняет черновик в окне. Отдельная правка заметки владения не мешает сохранению таблиц.
4. Удалить выбранное владение с другого клиента при открытом окне: старые действия/редакторы не меняют первое владение. Проверить отложенное изменение поля и переключение активного владения во время ожидания.
5. Попробовать занятый ID ресурса/локации и добавление дубля ID: запись отклоняется, старые ID и ссылки остаются целы. Проверить также неизменность существующих пользовательских дублей при несвязанной правке.
6. Закрыть окно с ожидающим рендером и с открытым FilePicker: поздний callback не пишет, окно не открывается само; явное повторное открытие работает, фокус/прокрутка сохраняются.
7. При системном reduced motion проверить статичную загрузку с подписью, сворачивание складской панели и граф боя; без этой настройки привычные анимации остаются. Проверить оба варианта загрузчика: изображение и Font Awesome.
8. Проверку реального импорта Laputa/rollback выполнять только по отдельному разрешению на тестовом мире. Подготовка кода не является выполнением импорта.
