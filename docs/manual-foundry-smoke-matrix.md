# FBL Skyhold: ручная Foundry smoke matrix

Целевая среда: Foundry VTT 13.351 + Forbidden Lands 13.0.5 и Foundry VTT 14.364 + Forbidden Lands 14.0.4.  
Актуализировано 3 октября 2026 года. Проверять на копии мира; эта редакция не является отчётом о пройденном запуске. Существующие отметки [x] сохранены как результаты прежнего списка, без подтверждения повторной проверки текущей версии.
Назначение: короткий воспроизводимый проход поведения, которое нельзя подтвердить Node-проверками.

## Preconditions

- мир запущен с актуальной версией модуля;
- открыты две сессии: authority-GM и обычный игрок с доступом к тестовому владению;
- для проверки layout доступны viewport 1360x900, минимальный поддерживаемый Foundry 1024x768 и узкое окно самого приложения;
- тестовое владение содержит жителей, строящееся и повреждённое здание, складские ресурсы/предметы, событие и активный либо архивный бой;
- перед проходом выполнены `npm run check`, `npm run ui:check`, `npm run css:check`, `npm run lint` и `npm run tenday:check`.

## 1. Shell, authority и навигация

- [x] Player: окно Skyhold открывается без console errors модуля.
- [ ] GM видит write actions; игрок видит только разрешённые действия.
- [ ] При отключении authority-GM player write actions становятся disabled/read-only до клика.
- [ ] Возврат или смена authority-GM обновляет статус без повторного открытия окна.
- [x] Основные вкладки переключаются мышью, активный раздел визуально различим.
- [ ] Holding selector переключает владение мышью без двойного render или потери состояния.

## 2. Карточки и списки

- [x] Карточка здания открывает editor одним кликом; editor закрывается кнопкой окна.
- [ ] Вложенные кнопки/селекты карточки выполняют только своё действие и не открывают editor повторно.
- [ ] Карточка складского помещения открывает связанное здание Enter/Space.
- [ ] Resident/storage search работает локально, сохраняет ввод и не сбрасывает scroll без необходимости.
- [x] Icon-only controls имеют понятные tooltip/accessibility names и достаточную кликабельную область.

## 3. Secondary windows и focus restore

- [ ] Building editor, crew editor, template browser, resource editor и random-event editors открываются один раз и получают focus.
- [ ] GM, вкладка «Работники»: четыре области профиля позволяют добавлять/удалять требования, менять группы И/ИЛИ, обязательность допуска, обязательные предыстории, типы, прошлое и черты; положительные и отрицательные проценты сохраняются после повторного открытия здания и шаблона. Для пересекающихся правил кнопка вверх меняет приоритет. Названия и проценты показаны в компактных строках без дублирующих чипов; заголовки и поля читаются на тёмном фоне. Пустые обязательные предыстории и пояснения свёрнуты. Заголовок «Прирост, %» показан один раз над каждым столбцом процентов. В прошлом и чертах кнопка списка раскрывает поиск с внутренней прокруткой; одновременно открыт один список, доступен ввод своего названия. В списках нет кодов групп. Для обязательного состава можно отметить несколько предысторий (ИЛИ) и количество людей; повторный выбор снимает отметку, список остаётся открытым. После сохранения и повторного открытия выбор сохраняется. Старые записи читаются совместимо; редактирование списка заменяет старое условие явными предысториями без подстановки черт или характеристик.
- [ ] Игрок видит профиль, но не может менять правила. На существующих назначениях после GM-правки обновляется производственный эквивалент; число голов и доступные QD не увеличиваются. Устаревшая правка из второго окна отклоняется с обновлением редактора. Открытие редактора само по себе не меняет профиль.
- [ ] Чертежи поселения: при широкой рамке слева компактный список, справа один паспорт. При сужении рамки выбор открывает паспорт, «К списку» возвращает каталог. Список и паспорт прокручиваются независимо, «В проект» остаётся доступной внизу.
- [ ] Компактные шаблоны: показатели развития находятся рядом с «Шаблоны» в заголовке окна и не дублируются при обновлении. Фильтры направлений — цветные иконки с подсказками. Поиск раскрывается и сохраняет состояние; свёрнутый активный поиск отмечен цветом. Шрифт паспорта совпадает с общим шрифтом модуля. Слева видны красные дефициты развития, репутация и довольство поселения; нулевые социальные бонусы скрыты.
- [ ] Строки шаблонов: бонусы справа от названия, дефициты справа от типа; обе группы одинакового размера, без знаков в чипах, с зелёной/красной полупрозрачной заливкой. Знак изменения остаётся в подсказке. Закрытые строки имеют красную рамку/заливку; построенные — золотую рамку и штамп «ПОСТРОЕНО». Для построенного обычного шаблона бонусы заменены галочкой; при `repeatSettlementEffects` бонусы остаются. Выделение строки не скрывает цвет её состояния.
- [ ] Чертежи: поиск по названию, функции, входному/выходному материалу работает без перерисовки на каждый символ. Если выбранное здание исключено поиском, его паспорт скрывается. Выбор результата, смена фильтров и внешнее обновление сохраняют запрос и прокрутку; Tab/Enter и возврат фокуса работают.
- [ ] GM и player: до завершения Центра Строительства зависимая ветка отсутствует в списке, поиске, категориях и счётчиках, включая GM-фильтр скрытых. Проект Центра не раскрывает ветку. Завершённый Центр раскрывает её; ремонт и временное отключение не прячут уже раскрытые чертежи. Разрушенный или заброшенный Центр не раскрывает ветку.
- [ ] Чертежи: «Можно начать», «Не хватает условий», «Построено», направление, назначение, этап и сортировка комбинируются. GM видит меню редактирования/удаления/видимости; игрок — только публичные шаблоны и разрешённое его ролью создание проекта.
- [ ] Паспорт чертежа: строительство, содержание, требования и производство разделены карточками; подписи и значения не смешиваются при сужении окна. У Рыбацкого причала условие о водоёме выводится один раз; разные условия участка и строительства сохраняются с отдельными подписями. Материалы «нужно / есть», бонусы, условия, ставки, обслуживание, допуск и производственные циклы совпадают с редактором. Недостаток материалов не запрещает добавить проект. Просмотр, фильтры и поиск не пишут данные мира.
- [ ] Escape закрывает popover/context menu/dialog там, где это заявлено интерфейсом.
- [ ] После закрытия secondary window focus возвращается к control, который её открыл, либо к логичному соседнему control.
- [ ] Повторный render во время ввода не переносит focus в другое окно и сохраняет selection/caret.

## 4. Preview/apply flows

- [ ] GM: кнопка «Десятник» открывает отдельное окно, а повторный клик фокусирует тот же экземпляр для выбранного владения.
- [ ] Само открытие, переключение вкладок и закрытие окна не меняют world state; повторное открытие неизменённого владения в той же browser session сохраняет подготовленный результат.
- [ ] Предпросмотр содержит «Сводку», «Хозяйство», «События» и «Точный diff»; пустые хозяйственные секции скрыты, а длинные списки не обрезаются молча.
- [ ] До commit случайные исходы не раскрыты: видны число общих проверок, пул репутации и подошедшие scheduled events, но не названия выпавших событий.
- [ ] Изменение владения либо влияющего каталога переводит окно в stale; Apply недоступен, пересчёт не создаёт частичного commit.
- [ ] Переключение активного владения в основном менеджере не меняет `holdingId` уже открытого окна и не направляет commit в другое владение.
- [ ] После «Провести десятник» в том же окне раскрываются фактические события, d100 появления жителя, GM-текст, ожидающие эффекты и все значимые `до → после`.
- [ ] Каждое событие с эффектами получает статус «Требует решения»; «Применить» меняет только его эффекты и статус, повторное применение недоступно.
- [ ] «Отложить» конкретного события создаёт одну запись плана на следующий десятник и не оставляет его в массовом apply.
- [ ] В «Журнале операций» кнопка строки десятника открывает read-only отчёт; просмотр не меняет world state и не показывает кнопку commit.
- [ ] Экономика, лечение/возраст, внутренние QD-часы, event history и operation payload появляются одной транзакцией (разделённое хранение выполняет несколько setting-write); повторный Apply недоступен.
- [ ] Ошибка создания ChatMessage не меняет успешный статус операции: окно показывает итог и отдельное предупреждение о чате.
- [ ] Публичная chat-карточка остаётся короткой и не содержит GM-only текст; GM-only событие видно в итоговом GM-окне.
- [ ] «Следующий десятник» готовит новый snapshot уже от записанного состояния и нового внутреннего QD-периода.
- [x] Player: batch storage preview перечисляет выбранный ресурс и целевое размещение; cancel ничего не меняет.
- [x] Player: worker assignment planner показывает назначения и очистку слотов; cancel ничего не меняет.
- [ ] Battle pending round показывает сохранённые dice/trace и не применяет последствия до Apply.
- [ ] Повторный Apply одного `roundId` не применяет последствия дважды.
- [ ] Terminal battle нельзя случайно продолжить; archive и aftermath доступны GM.

- [ ] Content pack показывает add/update/skip/conflict до записи, stale preview отклоняется, выбранные конфликты применяются один раз.
- [ ] Event effects preview атомарно отклоняет недостаток казны/ресурса; schedule/apply/archive отражаются в timeline.

- [ ] Random-event requirement/boost controls доступны мышью и удаляются только соответствующей кнопкой.
- [ ] Destructive reset/delete dialogs имеют безопасный default и возвращают focus после cancel.

## 6. Экономика и следующий перенос зданий

- [ ] До Apply обычная загрузка и Preview сохраняют прежний каталог без новых встроенных шаблонов и механических полей. Новый мир отдельно получает полный актуальный набор.
- [ ] GM Preview переноса v16 читает текущее сохранение, показывает 124+2 шаблона, пять новых заведений, замену механики связанных построек, удаление дополнительных шаблонов и блокирующие неоднозначности/незавершённые циклы. Исторический reset Лапуты не запускается.
- [ ] Изменение мира после Preview делает план stale; повторный Apply того же `operationId` не создаёт второй результат.
- [ ] После Apply и перезагрузки повторный Preview не предлагает новых изменений; повтор операции не выполняет вторую запись. Обычная загрузка сохраняет пользовательские правки; явная принудительная замена меняет механические поля в пределах Preview, а имена, состояния, жители, имущество и казна сохраняются.
- [ ] Сохранены фактические казна, партии, жители, кладбище, назначения, долги, рынок, экземпляры, стройки, незавершённые циклы и пользовательские настройки. Небезопасные сопоставления блокируют запись, не обнуляют состояние.
- [ ] Новые условия «Построить» не останавливают готовые здания и начатые проекты; условия «Работать» показывают причину отключения конкретной услуги. Дом собраний добавлен как шаблон, но не построен автоматически.
- [ ] Rollback восстанавливает согласованное состояние до переноса при корректном marker/hash; неверный hash не допускает подмены снимка.
- [ ] Player не может прямым patch увеличить казну/ресурс, подменить экономические поля здания или forged construction successes; разрешённые действия проходят authority-GM.
- [ ] План труда одного жителя не превышает 20 normal + 10 overtime QD; QD нельзя одновременно потратить на производство, обслуживание и полный доход постоялого двора.
- [ ] Зарплаты и содержание списываются до запуска функции; точная недоплата блокирует только адресата и исчезает после погашения.
- [ ] В каталоге v16 после переноса обычные здания имеют только денежное содержание; технические назначения тратят прямые QD конкретного жителя без второй операторской оплаты. Пропуск обслуживания и перенос прежнего backlog видимы по согласованным правилам; mothball убирает capacity/quality/shelf-life bonus без уничтожения товара.
- [ ] Питание расходует старейшие готовые партии, не ест raw Grain/Meat/Milk/Honey и не омолаживает партии при перемещении.
- [ ] Полностью выданный выбранный рацион сбрасывает Hunger; недостача повышает persistent Hunger и видимо уменьшает выпуск/внутренний спрос без автоматической смерти.
- [ ] Field/Garden проходят посев → рост → сбор; Pasture/Pigsty/Sheepfold используют целое поголовье, Feed, сезон и явный slaughter без печати Meat/Wool/Milk из пустого здания.
- [ ] Внутренний спрос расходует один бюджет источника; качество продавца меняет цену в диапазоне 0,5–1,5; scheduled-груз с шага 1 текущего Apply не продаётся до следующего десятника, локальная продукция продаётся сразу, а instant/manual-доставка между Apply доступна уже в первом следующем Apply.
- [ ] Player и GM создают входящий и исходящий заказ через одинаковый authority-путь; повтор команды не дублирует debit/reserve/order.
- [ ] Входящий stock и исходящий demand уменьшаются сделкой и восстанавливаются за 2–6 десятников; только что потреблённый demand не восстанавливается в том же Apply.
- [ ] Исходящий cargo остаётся на складе до dispatch, затем исчезает из точных FIFO-партий; выручка приходит только при delivery.
- [ ] `needsResolution` блокирует только одну поставку, скрытые seed/proposal не видны player, страховка выплачивается только после GM-resolution.

## 8. Performance observation

- [ ] Переключение вкладок на large fixture не вызывает заметной серии повторных renders.
- [ ] Resident/building/storage search не пишет world settings на каждый символ.
- [ ] После одной команды число settings writes соответствует dirty partition contract.
- [ ] Console не содержит повторной normalization в одном render cycle.
- [ ] Если действие ощущается медленным, записаны вкладка, fixture size, action и browser trace вместо общего описания «тормозит».

## Exit criteria

- нет blocker/critical ошибок;
- все основные сценарии доступны мышью; клавиатура требуется прежде всего для ввода в поля;
- нет controls без accessible name;
- GM/player authority contract совпадает с UI;
- destructive previews не допускают partial/stale apply;
- screenshots не показывают clipped actions или нечитаемый текст;
- найденные дефекты исправлены у текущего CSS/code owner и добавлены в автоматическую проверку, когда это возможно.

- [ ] Проверить рецепт с альтернативами и общим обязательным материалом: Preview и Apply списывают ровно один обеспеченный вариант плюс обязательные расходы; при нехватке обоих вариантов выпуска нет. Проверить режим за единицу выхода.
- [ ] После явного применения исправленных бонусов у Маяка и Лазарета нет Продовольствия; прочие бонусы сохранены.

### Довольство и вклад повторных зданий (2026-09-13)

- [ ] GM: нажатие на довольство открывает оформленное окно с текущим итогом, составляющими, шкалой и Контролем. Сумма составляющих совпадает с показателем поселения. Подробности жителей и зданий раскрываются и прокручиваются; длинные названия не перекрывают числа, закрытие доступно на небольшом экране.
- [ ] Игрок: окно доступно только для доступного поселения; скрытые имена, черты и индивидуальные GM-подробности отсутствуют. Открытие и закрытие не изменяют мир.
- [ ] Карточки зданий: у двух одинаковых работающих зданий неучтённые повторы развития/Репутации/фиксированного довольства скрыты. Отрицательное довольство, явно разрешённые повторные эффекты и фактический охват служб учитываются. После остановки первого здания вклад отображается на действующем экземпляре согласно расчёту. Категории и режим GM/игрок не меняют вклады.
- [ ] В редакторе исходные бонусы остаются доступны; их скрытие в карточке не стирает настройки. Досуг v16 требует фактических профильных QD и текущего штата, имеет повторы 100/75/50/25%, затем 25%, без ограничения числом жителей; номинальные поля шаблона не заменяют зачтённый вклад.

## Дополнительные проверки после аудитов сентября

- [ ] Два ГМ и игрок: разрешённая/запрещённая операция, неверный sender/target, одинаковый ID с тем же/другим содержимым, смена authority после записи до ответа; один результат, понятный конфликт.
- [ ] Изменить поле и сразу закрыть редактор; ошибка связи сохраняет незаписанный черновик. Закрытие при queued render/FilePicker не открывает окно и не пишет старым callback. Два редактора событий не перезаписывают чужое изменение.
- [ ] Новый custom resource и зависимость в одной операции; коллизия ID, удаление используемого ресурса и replace-import с зависимостями отклоняются целиком. Допустимый Preview не является разрешением Apply.
- [ ] Покупка/импорт: двойной клик, отмена, ошибка записи, смена Preview во время чтения файла, закрытие в процессе. Одна запись без самопроизвольного открытия окна.
- [ ] Складское меню: стрелки, Escape и возврат фокуса; batch, значение выше max. Ручное добавление ресурса GM-only. Отмена очистки логов/переселения/удаления отряда/связи не меняет мир.
- [ ] Окна рынка, корабля и боя после ошибки загрузки шаблона/стилей повторно открываются. Reduced motion сохраняет видимую подпись загрузки. Десятник не раскрывает gmText игроку; общий план обороны остаётся общим.
- [ ] Корабли: выполнить [отдельный smoke](ships-manual-smoke.md) и [проверку планировщика](ship-order-planner-smoke.md); маршруты: [проверку сети](route-network-smoke.md).
- [ ] Политика: Контроль до открытия кабинета; GM-записи/директивы/указ, оплата и сроки за один десятник, нехватка средств и повтор; игрок видит только доступные действия/публичную историю. Пакетный расчёт при Политике/дани не доступен.
